# Playback decisions

- Provider snapshots and progress events are independent observations. Progress-only snapshot changes must update shared transport state even with no pending selection.
- Progress reconciles through the existing observe function. It does not bypass identity/occurrence or pause/cancellation guards and does not convert elapsed time alone into confirmed playback.
- Compare against the previous native transport snapshot rather than the manager's normalized queue projection. This prevents normalized queue indices/totals from triggering reconciliation every tick.
- Transport comparison excludes position/duration, which already have a dedicated progress channel. It includes status, identity/title/artist, occurrence, queue total, shuffle, repeat and volume. Clock-only ticks continue updating the store and progress subscribers without playback-change emission.
- Spotify adapter tests deliberately omit one subscriber's transport event while leaving its snapshot/progress truthful. This proves recovery for a missed notification; it does not claim the current Spotify SDK always misses that event. Apple naturally has this event path because refreshProgress can assign currentPlayback without emitting playback changes.
- Keep HMR retention behavior unchanged: module-local manager WeakMap and retained auth runtime suggest possible duplicate wrapping, but no test proves this caused the user's symptom.
- Read global-patterns/SKILL.md. Its referenced /Users/vinicius/code/agent-context/global.md and mandated .better-coding-agents/resources are absent. Relocated references exist under /Users/vinicius/code/agentic-context. No new library API was introduced; existing pinned Jotai 2.20.3 store/get/set/sub pattern is reused.
- playProgressive returns the initial start promise; background completion errors are handled independently so a later album-page failure cannot make a successfully audible prefix appear failed. This method is only used after accepted playback, never speculative prefetch.
- A continuation may append only after the existing manager settles that selection and its current ordered context remains valid. It validates the full result starts with exactly the selected prefix. Prefix/suffix arrays are copied before asynchronous work can mutate source arrays.
- Capture epoch, play generation and queue mutation revision. Queue mutations invalidate waiting continuation at admission, before their asynchronous effect. Per-track provider appends allow cancellation checks between remote requests. An already accepted provider request cannot be undone; no abort capability is invented.
- Appending invalidates the original ordered context and total, matching existing queueAppend semantics. The native queue is refreshed on success or partial failure. Do not show the intended full list length as a confirmed native queue count.
- Each suffix append re-enters the shared command queue separately. Foreground seek/skip/volume operations admitted while a remote append is pending run before the next append. A single already-issued remote call remains non-cancellable.
