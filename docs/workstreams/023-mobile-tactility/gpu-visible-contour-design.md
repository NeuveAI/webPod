# Exact visible contour queries: design proposal

Read-only research for the next slice in `gpu-pack-flip-investigation.md`. No application changes, browser operations, protocol implementation, build or new profiling occurred. This is a proposed boundary, not a claim of feature completion or approved latency tradeoff.

## Updated immediate recommendation after the post-guard profile

The post-guard main profile changes the next implementation priority. Independently summed sampled stacks in `evidence/gpu-worker/pack-flip/post-guard-main.cpuprofile` confirm StickerCollection 926.671 ms inclusive; stickerProjectedQuad 524.319 ms inclusive / 193.170 ms self; StickerAppearanceEditor 347.992 ms; projectPreparedContour 215.411 ms; castSegment 202.791 ms. These inclusive values overlap and must not be added. This is one 7.424-second development trajectory, not a matched before/after performance ratio.

`stickerProjectedQuad` scans all UVs once for extrema, then scans them nine more times for four corners, four edge centers and center on every invocation. Only the subsequent world/camera projection changes under a rigid device pose. Therefore the smallest next slice is an exact geometry-revision cache of those selected local samples and their validity result, in `packages/device/src/sticker-transform-projection.ts`, with parity and invalidation proofs. It does not require an asynchronous API, historical display, or new worker ownership.

Cache at most one entry per live geometry using a WeakMap. Preserve the exact min/max scan, nearest-point tie order, distance threshold, attribute getters and nine returned positions. Key by position and UV attribute identities, backing arrays/interleaved data, versions, counts, itemSize, normalized and offset/stride, matching the project's prepared-geometry dependency pattern. Replacing arrays, changing UVs, deforming positions with a version update, or adopting a new carry geometry invalidates; unchanged rigid motion does not. The same source contract already expects mutation owners to publish attribute versions; do not claim to detect arbitrary unversioned external array mutation without inspecting it. Externally mutable geometry may need explicit opt-in admission rather than applying a cache globally—resolve from current callers before implementation.

Per call, still execute the original nine local-to-world/camera projections, finite/depth checks, zero-area rejection and canvas mapping using the **current** matrices. Do not cache projected coordinates by geometry alone. Do not replace exact vertices with bounds or derive center as average of corners. Preserve null results for invalid UVs, missing exact samples and clipping. A transformed valid local cache can still return null for the current camera.

Proof must compare all nine points and null decisions with the original function across static equipped and deformed carry, normalized/interleaved attributes, tied nearest UVs, zero extent, nonfinite values, geometry replacement, version/backing mutations, camera/layout changes and repeated pose queries. Count getter reads: first resource revision performs original scans; subsequent poses perform no dense UV scan. Retain source-parity and actual production-geometry cases. Then remeasure the same lead-owned trajectory before committing the larger worker design. This updates the dispatch priority; the following asynchronous design remains a researched future option for residual exact contour cost.

## Recommendation and unresolved latency gate

Extract one exact, resumable contour projection kernel, then run it through a bounded query owner shared by GL and native. Prefer extending the existing collision worker authority to retain an exact collider for queries. Do not run the current synchronous contour function on the native rendering worker: that would move the measured stall onto the worker responsible for motion, rendering, LCD uploads and command settlements.

There is an unavoidable acceptance question. A query that takes longer than a frame cannot simultaneously produce an exact contour for every current pose, never delay rendering, and never show an older contour. Latest-only rejection on every pose change can starve publication indefinitely during rotation. Finishing one admitted job avoids computation starvation but does not make its result current. This proposal preserves exact numerical results and current input authority; it does **not** silently authorize stale HUD display, skipped fade frames, frozen model rendering or approximate occlusion. Before shipping, measure complete-query latency and agree an explicit presentation policy if it exceeds the frame budget. A worker alone does not prove that the visible fidelity requirement is met.

## Source-backed boundary

- `packages/device/src/sticker-contour.ts`: prepared projection preserves Float64 local points, visibility samples along every span, path order, disconnected pieces, hole handling, four anchor visibility tests, camera clipping and screen coordinates. The measured branch is `projectPreparedContour`, not dense alpha tracing. Its current wrapper requires a MeshPhysicalMaterial/damage field even when the prepared data already exists.
- `packages/device/src/sticker-contour-preparation-data.ts`: `PreparedStickerContour` already supplies Float64 endpoint paths, sampled visibility paths and anchors. Its WeakMap checks geometry attributes, versions, backing storage, exact field and byte wear threshold. Use the adopted prepared geometry, not requested placement or future wear. Plain structured cloning cannot preserve that WeakMap association.
- `packages/device/src/sticker-visibility.ts`: the collider excludes sticker meshes and equipped-sticker ancestors, includes visible nonzero-opacity authored meshes, and uses content-local geometry. Visibility is `hit === null || hit.distance >= camera.distanceTo(point) - 1e-5`. Camera and world point are transformed through the same inverse content matrix. Repeated preparation is already cached by assembly authority; it is not the demonstrated hot cost.
- `packages/device/src/sticker-collision.ts` and `packed-collision-tree.ts`: exact Float64 coordinates/bounds, Uint32 traversal links and stable triangle order already form a data-only snapshot. Preserve left/right order, equal-distance tie behavior, two-sided triangle intersections, shared-edge roundoff fallback and every existing epsilon. A visibility-only early-out or new BVH algorithm is a separate change requiring separate proof.
- `packages/device/src/sticker-collision-preparation.ts` / `sticker-collision-worker.ts`: one global build producer, three queued owners and a 128 MiB estimate cap exist. Today completion transfers its snapshot to main and terminates the worker; there is no resident query server to call. Keeping a copy resident changes accounting and lifecycle and must be implemented explicitly, not assumed free.
- `packages/device/src/device-render-worker.ts` and `sticker-render-frame.ts`: native holds actual geometry and render-only damage texels. It does not receive prepared contour arrays or the main visibility snapshot. Native material nodes are not compatible with the current MeshPhysicalMaterial wrapper. Rendering geometry alone does not recreate the same prepared contour or occlusion authority.
- `packages/device/src/sticker-projection.ts`: one shared main projection handle resolves carried versus equipped displayed mesh. Its contour currently synchronously queries visibility. Picking, drop fitting and transform-plane input are separate methods. `captureStickerTransformPlane` already cancels against actual content/camera changes; it must not be rebound to the last completed asynchronous contour.
- `packages/device/src/device-render-protocol.ts`: existing `RenderPose` has logical sequence, motionEpoch, scene/resource/layout revisions and authoritative node matrices. Reliable settlements/checkpoints are independent of projection notification credit. Reuse those meanings; do not add a second pose clock or put contour completion behind projection ACK.

Pinned dependency research used `packages/device/node_modules/three/src/math/Ray.js` (`intersectTriangle`), plus the repository's collider wrapper, rather than an unpinned Three checkout. The resources directory has Bun transfer declarations (`resources/bun/packages/bun-types/globals.d.ts`) but no Three checkout in the inspected inventory; the installed dependency is authoritative. Modern-web-guidance search through bunx returned only generic performance guidance (similarity 0.38), not a canonical worker-query protocol. No external guide is used as proof of numerical or lifecycle equivalence.

## Proposed typed data boundary

Names below are design notation, not new committed APIs.

**Installed query resources:** one immutable assembly snapshot (`StickerCollisionSnapshot`) and one selected displayed-print contour (`PreparedStickerContour`), each identified by owner generation and exact resource revision. Include the exact local quad samples needed for center/degeneracy checks: current `stickerProjectedQuad` scans UVs and samples nine authored grid positions, so sending only contour anchors would not reproduce its admission. Prepare these nine samples once per adopted geometry using the existing getter/order logic, without changing precision or replacing them with bounding boxes.

**Request:** owner generation, editor session/selection token, request sequence, visibility generation, collider revision, displayed-print resource revision, adopted geometry/wear identity, complete pose stamp, content world matrix, print world matrix, camera world/inverse/projection matrices, and scalar canvas rectangle. Matrices retain existing number precision/order. Snapshot all fields together from the admitted query view; never mix a new camera with an old print or worker's moving pose. Do not send a mesh, callback, DOM object, texture or per-frame dense arrays.

**Result:** echoed full stamp and `StickerProjectedContour | null`, represented on the wire by packed Float64 screen points, path offsets/closed flags, four anchors/visibility flags and center. Derive exact worst-case result capacity from installed visibility sample counts, including split spans and anchors; reserve before computation. One acknowledged output credit prevents unbounded queued result copies. Main may reconstruct only the currently adopted result; no history keyed by pose.

Install contours through the existing transaction producer's private delivery (`acquirePrivateStickerTransaction` supports contour results through its default path). Keep its private-copy reservation and lease until the query owner acknowledges replacement or terminates. Do not fetch full damage fields or artwork for projection. Selected carry geometry lacking prepared contour must use the existing exact preparation authority; it must not silently fall back to synchronous dense contour tracing in the editor.

## Scheduling, cancellation and presentation

One active query plus one latest pending request per active editor; one resource candidate plus current resources; one output awaiting acknowledgement. Coalesce repeated main notifications into at most one request per animation frame. Equal complete stamps are no-ops. Hidden presence cancels demand without clearing retained selection; every positive fade value remains eligible. Presence-only spring progress does not change an otherwise identical query.

Finish an admitted pose query despite newer compatible pose samples, then execute the latest pending pose. New selection, geometry/wear resource, assembly, layout, visibility or owner generation cancels incompatible work. Thus continuous motion does not repeatedly abort all useful computation. On quiescence, the final pending pose must finish and publish; a terminal request cannot be overwritten by an older projection message. A newer genuine user intent may supersede it.

Batch both projection and ray traversal. Merely yielding between rays leaves a pathological single ray unbounded. Extract a resumable traversal preserving operation and traversal order, with per-job scratch; check cancellation after a fixed node/triangle budget and yield a macrotask after an elapsed budget. The repository's `yieldSteps` provides initial yield and 4 ms cooperative slices, but neither it nor typed-array allocation is a hard device-time bound. Avoid sharing mutable collider scratch between overlapping resumable jobs. Only one job executes at once per query owner.

Main admission rejects retired generation, wrong selection, incompatible resource/assembly/layout/visibility and nonmonotonic results. Keep the exact pose stamp on every result. Strict-current display would accept only a matching current pose; older results can be retained internally but must not masquerade as current. If an explicitly approved last-complete display policy is later chosen, it must be labeled as a measured latency contract and must never authorize input. Reprojecting old visible paths with a new matrix is **not** exact occlusion and is excluded.

Pointer/keyboard/tool editing reads current main intent and currently adopted geometry. A stale handle must not capture or mutate from a historical contour. Existing synchronous plane validation and final sample behavior remain. If the requirement excludes *all* event-time BVH work as well as contour sweeps, move handle admission to an asynchronous stamped request and retain the actual input sample/cancellation token; that is an additional input-contract slice, not a hidden side effect of replacing contour reads. No synchronous full-contour fallback is allowed on request failure.

## Worker placement and ownership

Recommended shared collision-worker extension avoids duplicating a native-only feature and preserves GL behavior. It changes the current one-shot worker into a leased query/build authority, retaining one current collider and at most one replacement for an active device. Existing prep queue must remain fair: a long-lived editor cannot occupy the build slot forever. Route bounded query slices and queued builds explicitly; do not spawn one worker per request or indefinitely retain every device owner.

Main still needs an exact collider for existing input/carry consumers. Where a resident worker keeps one copy and transfers another to main, reserve both arrays before allocating. Keep the existing 128 MiB cap; account resident, candidate, copy-in-flight and result storage, plus existing queued build reservations. No claim that the current cap automatically fits the new overlap: actual peak proof is a prerequisite. Prefer producer-side copying and one transfer; borrowed main arrays must remain intact. Release charges only after worker disposal acknowledgement or termination. Abort one query must not terminate unrelated admitted owners; whole-worker failure retires all of that worker's leases before replacement.

Alternative: native renderer worker can borrow its existing geometry, but still needs exact contour/collider installation and resumable query execution. It risks delaying presentation even with batching and needs a separate GL query path. It is viable only after a measured shared scheduling proof; it is not the smallest complete cross-backend solution. Extending the carry worker similarly couples this task to deformation/priming and does not provide a free GL/native query authority.

GL fallback uses the same asynchronous query owner and exact kernel. Renderer replacement invalidates backend-specific pose/resource bindings, while a retained query resource may survive only when its actual assembly and displayed geometry identity are proven unchanged. Worker failure cannot fall back to the current synchronous full sweep. Recovery must preserve already displayed resources, reject stale completions and either restore the query owner within a bounded retry policy or expose the existing recoverable failure state; behavior during unavailable queries needs explicit runtime validation.

## Smallest coherent implementation slices

1. **Pure exact resumable kernel and parity only:** `packages/device/src/sticker-contour.ts`, `sticker-collision.ts`, one adjacent data-only contour-query module, and focused proofs. Share math with current synchronous path; do not duplicate it. Prepared quad extraction may require `sticker-transform-projection.ts`. No UI behavior changes yet.
2. **Bounded resident ownership and transport:** `sticker-collision-preparation.ts`, `sticker-collision-worker.ts`, `sticker-visibility.ts`, adjacent typed request/lease module, and existing contour transaction private-delivery integration if needed. Prove total bytes and fair cancellation before selecting the transport. No change to render-control protocol is required for the recommended dedicated query path; reuse its exported stamp types.
3. **Shared displayed-print integration:** `sticker-projection.ts`, `sticker-contract.ts`, the existing prepared contour selector in `sticker-contour-preparation-data.ts`, and native/GL projection construction callers only as needed. Request only adopted equipped/carry frames; publish readiness independently of renderer projection credit. Exact caller manifest must follow implementation planning, not blanket permission to edit the render host.
4. **App owner and input admission:** `apps/web/src/production-device-view.tsx`, `sticker-editor.tsx`, and a small Jotai-backed query-result owner if needed. Subscribe/request outside render; use the result stamp in handle admission. Preserve positive exit, active human/tool draft behavior, errors and cancellation. Remove synchronous contour invocation from the render memo. Validate latency/presentation policy before activation.

## Objective acceptance evidence

- Exact old/new output across catalogue art, all wear thresholds selected at discontinuities, holes/disconnected contours, thin exposed edges, seam wrap, grazing/coplanar rays, camera clipping, zero-area quad and transparent/invisible authored surfaces. Compare path order, split/closed flags, anchor visibility and Float64 numbers; no geometric tolerance added by transport.
- Actual module-worker round trip using borrowed buffers whose bytes/detachment state are checked before/after. Current/candidate resource overlap, stale install, send failure, missing ACK, worker death, hide/resume, cancellation mid-ray, backend replacement and final zero ownership.
- Thousands of pose notifications under a held query: at most one active/one pending/one output credit, no linear queue growth, nonstarving compatible completion and exact final-pose drain. Incompatible resources never publish. Query work cannot gate native command settlement or projection ACK.
- Mounted human and tool editor: positive fade remains, fully hidden does no work, current-pose reopen, rapid selection change, wear/scale/rotation during preparation, drag cancel on pose/layout change, final release sample, retry and return-to-pack. No stale contour grants input.
- Actual GL and native matched runtime: no main contour BVH sweeps; no new renderer-worker stalls; measured end-to-end query/result age and pointer responsiveness, not only main RAF cadence. Cold preparation, normal/reduced motion, repeated flips and reversals, and resources held during active carry must fit the unchanged caps.

The resource plumbing and exact kernel are feasible with current types. The unresolved performance issue is total exact query throughput; batching prevents monopolizing a thread but does not reduce that work. If full results still lag materially, a separately proved exact traversal optimization is preferable to quietly relaxing the visual contract.

## Refined first experiment: throughput before transport commitment

Lead feedback correctly prioritizes a bounded exact scalar/batched traversal benchmark before committing the resident-worker architecture. The trace's `Vector3.fromArray` self cost makes this a credible candidate, but it includes development/debug instrumentation and is not proof that arithmetic alone consumes the same production time.

Use the existing collider snapshot and exact real prepared contour rays as the benchmark input. Prototype an isolated scalar traversal in evidence first, without replacing production `castSegment`: load vertex coordinates directly into local numbers; preserve the installed Three ray-box/ray-triangle operation order, two-sided tests, shared-edge fallback, nearest-distance comparisons, tie order and endpoint threshold. Do not introduce a simplified any-hit test merely because the final consumer asks a boolean. Batched evaluation should reuse immutable arrays and per-query camera values, not allocate Vector3 objects for every triangle. Compare full hit identity/distance and all contour outputs before using visibility-only parity as a weaker check. Scalar arithmetic reassociation, changed NaN handling or replacing distance with squared-distance comparisons can change boundary behavior; adversarial tests must expose those changes.

Run identical rays through current and scalar kernels in production-mode Bun and then, only through the lead, the installed Chrome worker at the same device/CPU conditions. Record warm/cold total query time, p95 and worst single-ray duration, allocation/GC, point count, node/triangle visits and output equality. Include the actual user's selected print/assembly, wrapped seam cases and deliberately high-intersection rays. A Bun speedup is useful screening, not browser proof. Run one bounded batch with no render measurement concurrently. This experiment can establish whether complete exact results plausibly fit the desired cadence; it does not justify stale display if they do not.

GPU compute is worth a separate measured candidate only if CPU throughput remains insufficient. The current query uses Float64 coordinates/points and JavaScript number arithmetic, whereas the renderer's ordinary WGSL path uses f32; translating the equations directly would not establish exact edge/tie behavior. GPU sample visibility also needs a result buffer/readback and synchronization before DOM grips can use it. Hardware depth sampling would change the triangle/endpoint and material-occlusion semantics and is excluded. A conservative GPU broad phase plus exact CPU refinement could preserve results only with a proved no-false-negative bound, including Float64-to-f32 conversion; that is appreciably larger scope than scalar batching. Do not infer GPU suitability from the existing WebGPU renderer alone.

Recommended immediate scoped dispatch: evidence-only current-versus-scalar batch benchmark and adversarial parity, reusing existing snapshots and pinned Three equations; no protocol/UI edits. Select CPU query-worker or a proved GPU-assisted boundary from measured throughput and exactness. This respects the GPU preference without making an unverified precision or readback tradeoff.

## Production follow-up: concrete off-main implementation plan

This section supersedes the earlier strict-current-display assumption and resident-build-worker recommendation for the first implementation. Production e940 still reports 87/83/95 ms tasks during positive dismissal at 6×. Moving the exact sweep off main is now the objective; the scalar experiment is optional subsequent optimization, not a prerequisite or justification to leave the full sweep on main.

### Freshness policy grounded in current behavior

The current synchronous sweep samples one admitted main query pose, blocks the main thread while calculating, then paints its result. Meanwhile native renderer motion can continue. Its result is already historical at presentation. Requiring zero-age worker results would impose a stronger contract and cause starvation without improving baseline fidelity.

Adopt **exact coherent sampled results, published monotonically within the current editor lineage**, with measured end-to-end age no worse than the production synchronous baseline. Every result is exact for its stamped pose, adopted print and collider. Do not transform old visible paths to a new pose or label the returned stamp as current. Continuous newer compatible requests do not invalidate a completed sample solely because a newer pose exists. On a stationary pose the last pending sample must complete exactly.

`sticker-collection.tsx:156–165` synchronously reads motionAuthority intent and dismisses the human editor on orientation change. `sticker-editor.tsx` retains shown selection for fade, but its `begin` refuses input when active state is null. The root also explicitly sets `inert={state === null || toolEditor !== null}`: both human dismissal and tool preview are non-interactive DOM presentations. Thus positive dismissal needs current sampling and authored animation continuity, not clickable historical controls. Keep this behavior. `stickerToolEditorAtom` is derived independently from property + held preview in placing/settling; collection-source tool carries are not necessarily cancelled by the human-editor dismissal. They must keep their own session/source identity and request new snapshots during orientation/preview changes.

A compatible lineage means the same editor session, selected sticker, source role (equipped or carried), backend owner generation and active visibility lifetime. Exact resource revisions may advance within that lineage during an ordinary scale/wear/rotation preview; a result from a previously **actually adopted** print is publishable only while its leased resource and lineage remain valid, its result sequence exceeds the last published one, and its layout/collider admission remains compatible. This models bounded presentation lag already present during synchronous calculation and async print preparation; it is not permission to display an unrelated placement, requested-but-never-adopted geometry, old selection or retired carry. Emit the resource revision with the result so consumers can distinguish presentation from authority. Source-role handoff, external placement replacement, new edit session, hide, layout invalidation, assembly invalidation and backend retirement are hard barriers.

The worker cannot prove the age budget from source alone. Record submission, worker start/end and main publication using the existing cross-realm time-origin convention. Acceptance requires matched production observations of age, main tasks and visible alignment during human fade and tool preview. Do not invent a subjective approval requirement: this is an objective runtime parity gate. Do not drop authored fade duration to meet it.

### Smallest complete transport

Use a **dedicated contour-query worker**, one bounded active owner per mounted projection authority, common to GL and native. This is a query consumer of existing prepared bytes, not a new geometry/BVH producer. Leave the current collision builder and renderer worker execution model intact. Its isolated synchronous exact sweep may finish even after a cancellation message is queued; main immediately suppresses incompatible publication, and the worker handles cancellation/replacement after the sweep. A watchdog can terminate the worker to retire an unresponsive generation. This is simpler and safer for the first implementation than rewriting ray traversal into resumable state and coupling it to renderer deadlines. Only one job can execute, so existing collider scratch remains valid.

Extract the prepared projection calculation into a pure shared function taking the exact prepared points, nine geometry-local quad samples, matrices, rectangle and visibility predicate. Keep the current synchronous function as a parity oracle/other-callsite boundary initially; the editor path must never call it to fall back. Reuse `createStickerCollision([], snapshot)` inside the worker, including exact endpoint threshold and all current math. Do not introduce the evidence-only scalar kernel in this slice.

Data-only protocol in one adjacent module:

- `install`: owner generation, install sequence, collider revision, contour/quad resource revision and private resources; reply `installed` or `failed` with the same identities.
- `query`: owner generation, editor lineage, monotonically increasing request sequence, exact installed IDs, coherent pose matrices/pose stamp and canvas rectangle, submitted time.
- `result`: echoed identities, exact `StickerProjectedContour | null`, start/end times. One result credit, released by `result-ack` only after main has consumed or explicitly rejected it.
- `cancel` / `release-resource` / `dispose`: generation-scoped, idempotent. Resource release acknowledgement identifies what is actually no longer reachable. A timeout terminates the generation before releasing its accounting.

One active query, one latest unsent query and one unacknowledged result; at most current plus candidate installed resources. At most one main publication per animation frame. New compatible pose replaces the unsent request, never repeatedly cancels active work. Hard barrier cancels main demand and clears its result immediately; it cannot promote a late answer. A terminal snapshot enters the same latest slot with sequence ordering; older projection notifications cannot overwrite it. New real user intent may supersede it. No arbitrary FIFO of pose messages and no geometry arrays per query.

### Exact resource delivery and accounting

The collider already has a borrowed packed snapshot on main. Use one explicit initially yielded, chunked private snapshot copy per collider revision, transfer it exactly once, and never detach mounted input/carry buffers. This follows the already reviewed carry-context snapshot discipline. A worker may borrow its own installed snapshot across jobs. Do not rebuild the BVH or reserialize the full render hierarchy.

Contour preparation already resides in the transaction worker. Add an optional exact contour descriptor to prepared contour metadata, using the descriptor/key already constructed by `preparePrint`. Do **not** append it indiscriminately to the existing surface/damage `preparedStickerResources` list: native render assemblers consume that list with their existing assumptions. Export a validated contour descriptor selector alongside `getPreparedStickerContour`; retain geometry/field/wear validation. Acquire a private contour lease through the existing `acquirePrivateStickerTransaction` path and deliver it directly to the query worker. No full damage field, texture or artwork needs to cross. Existing transaction private-byte accounting remains in force until replacement acknowledgement/termination. For supported carried geometry, ensure the exact currently prepared contour exists before install; unavailable metadata triggers existing preparation/readiness, never main dense tracing.

Do not add an independent unaccounted 128 MiB allowance for collider copies. Extend the existing collision preparation accounting through a small shared reservation interface: resident query snapshots, candidate snapshots, copy-in-flight and active/queued collision builds share the **existing** 128 MiB cap. Charge before allocating; release only when the private owner is retired. Reserve contour result buffers from a bounded output budget derived from installed point counts, with current plus one pending result maximum; make this budget explicit and include it in the same query reservation. Contour private bytes remain charged by the transaction broker rather than counted as free because they arrive through a port. Prove combined actual default-device overlap before activation. If the cap rejects, retire candidate resources safely and keep current presentation/input intact; no cap increase or hidden synchronous worker-failure fallback.

### Exact initial file manifest

New shared modules (names proposed):

- `packages/device/src/sticker-contour-query-data.ts`: validated data-only install/query/result identities and shape types.
- `packages/device/src/sticker-contour-query-worker.ts`: installed immutable resources, exact sweep, one-credit result, retirement.
- `packages/device/src/sticker-contour-query.ts`: main owner, snapshot copy/transfer, install acknowledgement, latest request scheduling, result subscription and accounting.
- `packages/device/src/sticker-collision-budget.ts`: extract the existing collision reservation state, retaining the old cap and queued-build semantics while admitting resident query reservations.

Existing files:

- `sticker-contour.ts` and `sticker-transform-projection.ts`: extract exact prepared/quad-sample projection reusable in worker; coordinate with the now-reviewed UV-index cache, do not overwrite it.
- `sticker-contour-preparation-data.ts` and `sticker-prepared-damage.ts`: retain/select the existing contour descriptor for private delivery without changing preparation math or cache identity.
- `sticker-collision-preparation.ts`: use the shared accounting helper, otherwise preserve build behavior.
- `sticker-projection.ts` and `sticker-contract.ts`: own the query service, select actual carried/equipped displayed resources, expose request/read/subscribe rather than synchronous editor sweep, dispose with the existing projection owner.
- `apps/web/src/production-device-view.tsx` and `sticker-editor.tsx`: bridge the typed query handle, Jotai-backed result subscription and demand outside render, keep hidden guard and current-authority input handlers.

No render-control protocol, native rendering worker, material, scalar intersection kernel, geometry producer, collection state-machine or motion-driver edits are required by this plan. GL `StickerPackScene` and native-sticker-controller already construct/dispose the shared projection owner; inspect whether subscription plumbing can use existing onProjectionReady without changing these callers. Add a caller file only if its concrete lifecycle wiring requires it, not by blanket host scope.

2.
