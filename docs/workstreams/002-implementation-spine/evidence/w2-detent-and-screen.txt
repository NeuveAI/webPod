W2.2 / W2.3 — the detent reducer, the coast, and the screen state machine
=========================================================================

001 §4.4's four input paths plus the programmatic seam, 001 §4.4's inertial
coast, and 001 §4.2's menu hierarchy with push/pop and a highlight index.

The rule that dominates: arrow keys are exactly one detent, always, with no
acceleration, ever. The test that guards it drives 40 keydowns 5ms apart — far
faster than any human or any OS auto-repeat, and far over every arc
acceleration threshold — and asserts the highlight moved exactly 40 rows with
`multiplier === 1` throughout.

Two things changed in response to review:

- The page size is no longer a field on the keypress. It is a parameter of the
  reducer call, supplied by the store, which is the only thing that knows the
  density. A caller can no longer page by a number that disagrees with the
  glass.
- `DetentOutcome.accelerated` is new, because `multiplier` could not carry the
  "did the device move further than it was told" question — `Shift+Arrow`
  makes it a viewport, which is not acceleration.

The coast is new: 001 §4.4's Release row, previously absent and undisclosed.
`endGesture` keeps the momentum and `coastStep` decays it at 0.94/frame,
firing a detent every 15° until |ω| < 60°/s. Every coasted detent still clicks,
and obeys the silence rule through the source the accumulator carried out of
the gesture.
