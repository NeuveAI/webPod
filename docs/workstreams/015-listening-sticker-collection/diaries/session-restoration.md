## Cause and change

MusicKit configure and progressive navigation data preceded sticker runtime startup. That runtime cleared inventory then awaited POST /api/stickers/session, whose ordinary server path verifies Apple authorization and imports upstream music before returning inventory. The existing GET /api/stickers already validates the native session and reads SQLite without Apple. The correction starts that GET before MusicKit configuration, publishes only validated inventory, then preserves it while the same provider becomes authorized and starts passive ingestion. No server, schema, grant policy, identifier or rendered UI source changed.

Owned files: apps/web/src/music-runtime.ts, apps/web/src/sticker-runtime.ts, apps/web/src/sticker-runtime.test.ts, apps/web/scripts/sticker-restoration.integration.test.ts. The existing place/open/listening APIs and immutable placement authority remain in use.

## Authority, ordering and lifetime

A successful native GET is the authority for early owned content; browser storage is not. A successful MusicKit configure with no session is definitive unauthorized, so it clears and revokes. Explicit permission-denied, observed authorized-to-null events, logout and provider replacement invalidate the generation and abort pending work. A rejected configure is uncertainty and retains the valid native lease. This mapping was verified against packages/providers/src/apple/apple-provider.ts configure (745–756), authorize (761), unauthorize (763) and token-refresh handling (629), and independently confirmed by the reviewer. Preconfigure default signed-out is not itself proof of logout.

GET 401/403 clears stale collection; network/import failures retain it. Same-provider transition preserves the validated snapshot. Background initial/retry imports deduplicate, measured listening attaches as soon as authorization and existing inventory allow, and a owned interval refreshes every fifteen visible minutes. Visibility return refreshes an overdue tab. Teardown cancels interval, visibility/session/listening subscriptions and fetches. No token is stored or logged.

Each inventory publication increments a local ordering counter. A delayed GET/import/mutation response with an intervening publication or older placementRevision must reread authoritative SQLite, bounded to three additional reads. This protects same-revision pack-open state as well as placements while admitting newly earned access. Under sustained overlapping writes beyond that bound, retain the last validated newer snapshot; the next passive read can converge. Existing serialized writes and generation checks remain intact.
