# D8 diary

## 2026-09-04

- Measured the authenticated route with Chrome DevTools. The shell was fast (343 ms LCP), while the runtime held the UI in its pre-authorized phase for about 26.2 seconds.
- The network panel showed 38 collection-page requests: 2 playlist pages, 3 artist pages, 5 album pages, and 28 sequential song pages. Token, storefront, and optional-stations traffic brought the inspected fetch/XHR total to 41.
- Replaced all-or-nothing hydration with a first-page barrier and subscribed background pagination. The same source object owns every page so navigation remains stable.
- Replayed a cache-bypassed authenticated navigation. The authorized state was present by the end of the 0.9-second navigation call; LCP was 477 ms. Background Apple traffic continued for roughly 11 seconds without blocking use.
- Verified the official v3 SDK can load only after temporarily hiding Vite's browser `process` shim, and that its content API is `api.music(path, parameters)` rather than the v1 convenience methods.
- Migrated the provider to MusicKit v3, its generic API, and `nowPlayingItemDidChange`. Kept the legacy facade as a unit-tested fallback.
- Corrected the EME probe: this Chrome session supports Widevine for temporary AAC/CENC playback, while the old persistent-state probe produced the misleading `neither-supported` result.
- The authorized live replay exposed three playback-specific incompatibilities: MusicKit v3 treated Vite's restored `process` shim as Node during `configure()`, rejected an attempted queue containing the complete multi-thousand-song library, and emitted singular item types such as `song`.
- Kept the shim hidden through configuration, bounded track queues to 100 items around the selection, preserved the full-list offset, and normalized singular v3 item types. Playback then reached MusicKit playing state 2 with a 96-item playable queue.
- Added provider progress polling because the v3 time event is not reliable in this runtime. The LCD advanced from 0:00 to 0:11 in step with MusicKit and did not show a false timeout.
- Added sanitized queue/play resolution telemetry, bounded causal retention, a copyable diagnostic report, and a stable development-only browser hook for future agent debugging.
- Closed transport ownership gaps: entering the root pauses the active provider, Play/Pause from the root returns to Now Playing, and switching to fixture data pauses Apple before replacing its controls.
- Final live replay proved root-entry pause, root Play/Pause resume plus Now Playing navigation, and a safe Apple-to-fixture switch. A deterministic regression also proves that returning during an unresolved SDK `play()` cannot restart hidden audio afterward. Automated verification is green at 1,273 tests and 78,592 assertions.
