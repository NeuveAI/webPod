# Exact projection sample selection reuse

Base8d95ff9ad28ab11852b19963c96544bee975998c; scope gpu-projection-sample-cache-scope.md. Only production change: packages/device/src/sticker-transform-projection.ts. No browser, state, packet timing, geometry, shader or worker protocol edits.

The cache retains the exact nine UV-selected vertex indices, not projected points or position values. Every query still reads nine current local positions (27 scalar components) and uses the original world→camera→projection operations, clipping, winding and area logic. This refinement was approved by lead: free-carry deformation helpers use setXYZ before aggregate publication and do not all bump position version themselves. Reading positions live preserves even unversioned changes and replacement without a new producer contract.

Admission is deliberately conservative. Only geometry whose existing preparedStickerContourWear check validates its prepared contour dependency stamp can reuse selections. All unknown/public geometry rescans using the original exact selection math, including arbitrary unversioned UV writes. The cache is a WeakMap keyed by UV attribute; one dependency stamp and nine indices (or invalid result) per attribute, with no pose history. The stamp contains attribute backing typed-array identity, buffer, byteOffset/byteLength, count, itemSize, normalized, interleaved data identity/version/stride/offset and getX/getY identities. New attributes get distinct keys. Version/layout changes invalidate; loss of prepared geometry authority falls back. Geometry index does not participate in UV nearest-vertex selection but the existing admission authority checks its stamp too. Prepared authority is itself based on versioned attributes: raw unversioned mutations to an already-adopted prepared UV violate that producer contract and are not magically detectable in constant time.

## Canonical mutation research and coverage

Installed Three0.185.1 BufferAttribute and InterleavedBufferAttribute getX/getY implement normalized reads; interleaved getters use data stride and offset. Interleaved needsUpdate forwards to data.version. setXY/setXYZ do not automatically increment version. Hence blanket caching unknown geometry would change public behavior and is rejected here.

sticker-surface.ts creates position/UV arrays before publication and only later mutates positions for folds; sticker-free-carry.ts reads UV and deforms positions. sticker-carry-computation.ts publishes completed positions with needsUpdate and new worker outputs; sticker-paper-transfer.ts restores fresh position/UV attributes. sticker-prepared-damage.ts preparePrint borrows completed geometry and registers the exact prepared contour after all work succeeds. No authored post-adoption UV mutation was found in these consumers. Replacement carry results acquire new prepared wrappers; sharing retains immutable UV resources. Local positions remain live regardless of these observations.

Production coverage is by path, not an invented runtime percentage: native-sticker-resources.ts equipped, native-carry-resources.ts carried, and ordinary native-pack-resources.ts query prints all call preparePrint with contour preparation enabled, so their committed query prints qualify while stamps match. GL usePreparedPrint follows the same preparePrint registration. Material-only warmup explicitly disables contours and does not qualify; it is not an interactive query print. Unknown/custom geometry, pending/unprepared surfaces, and modified prepared stamps stay uncached. No numeric cache-hit coverage is claimed without runtime instrumentation.
