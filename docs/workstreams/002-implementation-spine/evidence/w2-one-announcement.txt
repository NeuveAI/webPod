W2.4 / U13 — a 30-detent flick produces exactly ONE announcement
================================================================

001 §4.4 and gate U13: the detent settle is debounced to a single
`aria-live="polite"` summary 350ms after motion stops, with no live-region spam
during fast scroll.

⚑ This gate previously INVERTED in a real browser and the tests did not see it.
`startAnnouncer` defaulted its clock to `Date.now()` while comparing against
`timestampMs + 350`, and the idiomatic browser value for that field is
`event.timeStamp` — on the `performance.now()` origin, ~1e4 against ~1.8e12.
Every due time looked long past, so a 30-detent flick announced 30 times. The
tests missed it because their fixtures fed `Date.now()`-based timestamps: the
requirement lived in a fixture rather than in the design.

The fix is structural, not documentary. There is now one clock per device,
held in `clockAtom`; the announcer stamps movements with it and the driver
reads it. No caller-supplied timestamp reaches any comparison, so the two
scales cannot diverge. A caller's `timestampMs` is used only for differences
inside a single gesture, where its origin does not matter.
