# W3 diary — Panel DOM

Implemented the 272×204 panel as semantic React DOM, deliberately independent of the device renderer and HTML-in-canvas integration. S03, S08, and S13 share the singleton `deviceStore`, use the Apple-shaped fixture provider, and are keyboard navigable (arrows, Enter, Backspace/Escape). Both explicit colourways render together at `/`.

The implementation includes all eight prescribed states, the three-stop S13 centre cycle, fixed 21px title geometry, eight 26px loading rows, sharp-artwork clamping, TanStack virtualization beyond 100 rows, one live region, preference media queries, and no component-local state. Provider playback is commanded on the S08→S13 transition and S13 subscribes to both playback and progress. Initialization moved into a document-scoped effect; server rendering is pure and the route is client-only.

The correction pass replaced label-only state handling with per-screen state behavior, made Dynamic Type reachable at 130% and 200% with 8/6/4 density, added exact pale/dark adaptive artwork fixtures, removed every authored sub-11px final font, and added semantic selected options plus browser-level keyboard and axe checks. The >100-row path uses a 120-row fixture and records both bounded DOM and a 4× CPU-throttled frame measurement.

The W6 boundary review caught that the adaptive bloom still depended on CSS blur and blend modes, despite the panel’s raster-safe contract. Those effects were replaced with a pre-composited radial colour field: no `filter`, `backdrop-filter`, or `mix-blend-mode` remains in the panel package. A package-seam browser test checks computed pseudo-element styles in both colourways and proves reduced transparency removes the field.

The second re-review correction moved the normal S13 path onto the fixture provider's real same-origin `/artwork` URL. The visible `<img>` and adaptive samples now share that exact URL. Raster formats use `ImageDecoder`; the fixture proxy's SVG uses an already-decoded `HTMLImageElement` wrapped in `VideoFrame`, with no canvas. A reference-counted 250ms clock continuously drives the timer-free fixture provider and cancels only after the final colourway unmounts. Browser evidence records 750ms of progress across an 800ms observation.

D-019 is now applied literally: offline screens show cached shell/art/metadata and no Downloads row, download glyph, downloaded count, or recovery action. S08 success creates a real fixture playlist, re-reads the playlist library total, and renders the returned object key; Strict Mode remounts observe the same cached operation promise rather than duplicating or losing it. The focused application owns `aria-activedescendant` with per-panel unique IDs, and axe evaluates a genuine Love button target in each colourway rather than reporting a vacuous zero-node pass.

The final target-size re-review exposed that the 2× owner preview had hidden a native 24px control. The Love button is now genuinely 44×44 in the panel's own layout coordinates. A -10px inline margin on each side preserves its former 24px flex footprint; the before/after provider screenshot is byte-identical. The browser gate reads native `offsetWidth`/`offsetHeight` and computed minimum sizes before preview zoom, while axe remains a separate composited-page check. Replaying the reviewer's exact 20px mutation makes both the deterministic source test and isolated Playwright test fail.

Visual work was compared through Pencil MCP against `A76Ib`, `DLqSo`, `H4QpB`, then the reusable S03/S13 nodes `HYNXu` and `mObBW`. Evidence includes paired overviews plus 544×408 locator crops for all 48 screen/state/colourway combinations, real-provider S13 crops, four adaptive-art test vectors, four Dynamic Type variants, and six preference variants.

Owner-only gates remain open: U14 thumb-occlusion validation and H-6 aesthetic acceptance in both colourways. This lane does not claim either passed.
