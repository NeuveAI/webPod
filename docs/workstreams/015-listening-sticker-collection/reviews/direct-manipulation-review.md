## Current implementation facts and likely failure boundaries

These identify work and review risk; they do not assert a finished new implementation is defective.

- `sticker-interaction.ts:setStickerRearVisible` currently admits tease even when inventory/pack is null. Readiness must react to inventory/art transitions while already facing rear, not only a front/rear threshold change. `refreshStickerCollection` changes status to loading without clearing valid inventory; status alone is an unsafe readiness predicate. Initial start/session replacement does clear inventory and must not expose another session's cached collection.
- `sticker-collection.tsx` currently binds “Slide out the sticker sheet” to onClick, uses a separate click-only close action, and calls commands.remove directly from detail. Current placed StickerSurface meshes have no direct pickup path. Renaming these controls does not satisfy physical pulling, lifting or returning.
- Existing `sticker-runtime.ts:107–145` serializes revisioned writes; placeSticker replaces only the matching ID and reads inventory when the queued write executes. removeSticker filters only that ID. Repository transaction rejects stale revision, duplicates, unowned IDs and out-of-bounds placement. Reuse these contracts rather than adding an endpoint or constructing a stale full-layout PUT at pointerdown.
- Persisted placement and transient carry must be distinct. Capture source placement, origin kind, pointer offset and operation/session generation. Temporarily hiding the source print must not remove its authoritative placement; successful server publication must not produce a second equipped copy while the carried mesh still exists. Failed move restores source coordinates; failed return leaves source equipped. Sheet-origin miss returns to sheet, rear-origin miss returns to rear: one unconditional return-to-sheet helper is insufficient.
- A slow response may complete after a new selection, another pickup, collection switch, close, face flip or logout. It may legitimately update current-session server inventory, but must never seize current gesture presentation, restore old-session state, announce the wrong sticker or move focus to a superseded control.409 reconciliation can introduce a newer canonical layout; do not restore a stale drag-start snapshot over it.
- Picking and placement must use actual world/camera/rear geometry with the same handedness and transform used by rendering. Preserve the point under the pointer; do not snap pickup to the print center. Alpha/cropped bounds and overlap ordering must decide which visible sticker is picked without a transparent rectangle stealing a device flick. A minimum accessible touch target can supplement, not conceal, correct visual hit behavior.
- Pointer ownership must cover packet pull, liner pull, sheet peel, rear lift and device rotation as mutually exclusive lanes. Release ownership before native capture release to avoid recursive lost-capture actions. Ignore extra/nonprimary pointers; test touch cancellation, reversal, resize and rear hiding while held. Stale geometry/projection handles after Canvas context loss cannot admit writes.
- Return-to-own-pack must remain reachable while the mobile packet is lowered for rear placement. Define visible seat/packet targeting and restoration with the designer before code; no hidden target or single magic pixel. Switching collection during a held sticker cannot silently return it to a different genre.
- Demand-render/profile review must inspect per-frame geometry/material allocation, buffer upload, repeated normal recomputation, React/DOM work and invalidation. Existing paper mesh generation is a hypothesis for profiling, not an established cause. Preserve shared texture ownership and dispose stale generated resources; no permanent loop or second light/renderer may conceal an expensive path.

## Program preparation lifecycle design review — implementation pending

The pinned Three0.185.1 `WebGLRenderer.js:1487` implementation calls `compile`, then repeatedly reads `properties.get(material).currentProgram.isReady()` from an internal10ms timer. It exposes no AbortSignal or cancellation handle. Material disposal removes those properties (`WebGLRenderer.js:1153–1155`), while context restoration replaces renderer internals. Ignoring a late promise resolution does not cancel this internal polling. The proposed correction addresses a concrete lifecycle incompatibility, not an assumed performance bottleneck.

The public `compile` method can initiate identical material preparation; a narrow adapter may then capture and runtime-validate program handles immediately and own bounded, cancellable readiness polling. This includes a pinned internal compatibility seam, not an entirely public supported abstraction. Pinned `WebGLProperties.get` returns `unknown`, and the type definition omits runtime `isReady`; validate that shape explicitly instead of broad `any` or asserting an unverified Three type. Public `compileAsync` with `Promise.race` does not solve cancellation. Synchronous GL completion calls would block the main thread and are not an equivalent responsiveness-preserving substitute.

Before approval, require owned cloned materials with custom shader callbacks/cache keys preserved, borrowed geometry/maps never disposed, abort/context-loss/unmount and timeout cleanup, truthful invalid-handle failures, and exactly-once completion. Critically, disposing the sole compiled owners immediately on success can release/delete the cached program (`releaseMaterialProgramReferences`); readiness must retain program-owning materials for the active prepared subscription or prove another live material already owns the same cached program. Context restoration must start from fresh handles.

`WebGLProgram.js:994` returns ready immediately when parallel shader compilation is unavailable. That fallback does not certify completed GPU work; the after-profile must identify extension availability and separately measure synchronous compile cost. No change to artwork, physical geometry or visible material variants is justified by this lifecycle adapter. Exact helper implementation and final native/profile evidence remain pending.
