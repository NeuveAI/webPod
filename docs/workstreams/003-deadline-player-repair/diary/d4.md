# D4 diary — `THREE.Clock` warning diagnosis

**Date:** 2026-09-03
**Implementer:** `/root/d4_three_clock`
**Status:** transitive limitation documented; no application or dependency change proposed

## Outcome

The repeated warning is not constructed by webPod. Every React Three Fiber root created by the installed stable `@react-three/fiber@9.7.0` initializes its store with `new THREE.Clock()`. The installed `three@0.185.1` marks that constructor deprecated and emits the warning from the constructor. A fresh T1 browser mount reproduced one warning and an instrumented stack crossed directly from Three's `Clock` constructor into Fiber's `createStore`.

No safe bounded implementation is available in the current stable dependency line:

- `9.7.0` is the npm `latest` Fiber release and still uses `Clock`.
- Fiber 10 has removed this store clock in favor of a scheduler, but the published line is currently `alpha`. Adopting it would be a renderer migration, not a warning-only patch.
- Rolling Three back before r183 removes the warning but also removes `HTMLTexture`, which webPod's T1 HTML-in-canvas composite requires.
- Passing a clock-like object to `<Canvas>` cannot prevent the warning because Fiber constructs its default store clock before canvas configuration.

Per the dispatch guardrail, I did not suppress `console.warn`, transform dependency output, patch `node_modules`, downgrade Three, or put an alpha renderer into the deadline branch.

## Source grounding

- Installed Fiber ESM: `node_modules/.bun/@react-three+fiber@9.7.0+c322101a3e22b31d/node_modules/@react-three/fiber/dist/events-156d8d12.esm.js` constructs `clock: new THREE.Clock()` in `createStore`.
- Installed Three source: `node_modules/.bun/three@0.185.1/node_modules/three/src/core/Clock.js` emits the exact warning and marks the API deprecated since r183.
- Published package metadata reports stable/latest Fiber as `9.7.0`; `10.0.0-alpha.4` is tagged `alpha` and introduces the `@pmndrs/scheduler` architecture.
- A clean inspection of the published `three@0.182.0` package found no `HTMLTexture` source or export.
- The repository-referenced `~/code/agentic-context/` directory was not present in this checkout. I therefore grounded the decision in the exact installed sources plus clean published package archives and did not infer undocumented behavior.

## Verification summary

- T1 Chrome reproduction: one canvas, `data-composite-tier="T1"`, one exact warning per fresh Fiber-root mount.
- Instrumented browser stack: `three ... warn` → `new Clock` → `@react-three/fiber ... createStore`.
- Device/composite tests: 299 pass, 0 fail. The mounted Fiber tests independently repeat the same warning once per root, which further confirms the source.
- Device TypeScript: clean.
- Composite TypeScript: clean.
- ESLint: clean.
- Client and SSR production builds: clean.
- Production client asset scan contains no exact deprecation literal; the warning is a development-time dependency diagnostic in this build, not a shipped UI failure.

Full sanitized evidence is recorded in `../evidence/d4-three-clock-diagnosis.md`.

## Residual risk and follow-up trigger

The development console remains noisy on every fresh Fiber root and mounted Fiber test. It should be revisited when a stable Fiber release removes `Clock` and that release passes webPod's T1 composite, demand-render, input, lighting, and pixel-density gates. Until then, masking it would reduce diagnostic truth and a framework prerelease would carry much greater demo risk than the warning.

No commit is proposed for product code. The workstream documentation can be included in the final evidence/handover commit.
