## Finding

### Minor 1 — the pure tier classifier and descriptor walker have no deterministic regression test

**File:** `packages/composite/src/capabilities.ts:236-279,497-526`

`resolveTier()` is a pure four-branch classifier, and `arityOf()` contains the
getter-safety invariant that originally made the flag-on route crash. Commit
`8208ccc` added no companion test file, and the current composite suite still
does not exercise either function directly. The committed two-browser evidence
and this independent reproduction prove the reviewed implementation is correct,
so this is not a merge blocker. A later refactor could nevertheless reverse T3
and T4 precedence or reintroduce direct accessor reads while scoped tests remain
green. Add table tests for `resolveTier` and a synthetic accessor/function
prototype-chain test for the descriptor walker when this detector is next
changed.

## Independent verification

### Flag-off detection reproduced

Chrome 151 was launched with
`--disable-blink-features=CanvasDrawElement` against the current
`/_probe/capabilities` route. It reported:

- WebGL1 and WebGL2 available;
- `requestPaint: false`;
- no `layoutSubtree` reflection;
- neither WebGL candidate name;
- no geometry generation;
- resolved and capability tier `T3`.

After removing timestamp and environment-only fields, the complete runtime
report — including all probe groups, notes, entry-point verdict and geometry
verdict — diffed identically against
`evidence/w6-capability-probe-flag-off.json`.

### Getter-safe flag-on detection reproduced

Chrome 151 was also launched with
`--enable-blink-features=CanvasDrawElement`. The route completed as T1 and
reported bidirectional `layoutSubtree` reflection. Independent descriptor
inspection found `HTMLCanvasElement.prototype.layoutSubtree` has a getter and no
data-property value; directly reading the member from the prototype threw
`TypeError: Illegal invocation`. The implementation at
`capabilities.ts:252-263` walks descriptors and reads only
`descriptor.value`, so it does not invoke that getter. This validates W6-D5 and
the flag-on evidence rather than merely restating it.

### WebGL name and arity are truthful

Flag-on Chrome exposed `texElementImage2D`, not
`texElementSubImage2D`, with declared arity 3. The probe classified that as the
current `(target, internalformat, element)` signature. This matches exactly:

- `html-in-canvas/Examples/webGL.html:59-72`, whose try/catch spans the
  three- and six-argument signatures of the same `texElementImage2D` name; and
- `three.js/src/renderers/webgl/WebGLTextures.js:1257-1319`, which tests the
  `texElementImage2D` name and selects its Chrome 150+ call when `.length === 3`.

The evidence correctly separates name churn from signature churn. It does not
claim that the demo's try/catch proves the separate rename.

### Geometry conclusion is accurate, with one terminology distinction

Flag-on Chrome exposed `getElementTransform` at arity 2 and did not expose
`updateElementGeometry`, `clearElementGeometry`, `getCanvasTransform`, or the
geometry-update event surface. The probe therefore accurately identifies the
older/shipped generation and correctly rejects the dispatch's original mandatory
`updateElementGeometry` call.

The evidence itself is precise at
`w6-capability-probe-chrome151.txt:114-127`: `getElementTransform` returns a
matrix that can be written as a CSS transform, while Three's current
`InteractionManager` computes the MVP/viewport matrix itself and writes the same
kind of `matrix3d`; it does not call either geometry helper. Thus “same
mechanism” in later prose means the same genuinely transformed-DOM outcome, not
the same browser method call. The approved downstream implementation is
consistent with that outcome: it uses `InteractionManager`, and its flagged
browser resize, native hit-test, focus and accessibility checks passed.

### Route naming and downstream integration

At `8208ccc`, TanStack's pathless `_probe` filename generated `/capabilities`.
The W6.0 diary disclosed that behavior. Commit `698f882` later renamed the file
to `[_]probe.capabilities.tsx`, and the current generated route correctly serves
`/_probe/capabilities`. This is a closed historical naming issue, not an active
finding against the final W6 boundary.

Production composite code contains no call expression for
`texElementImage2D` or `texElementSubImage2D`. It delegates upload churn to
Three `HTMLTexture`; the current static invariant test also rejects a raw call.
The approved implementation's T1 detection, Jotai tier publication, context
loss/restore, `InteractionManager` geometry, SSR boundary and zero-idle-rAF
behavior are consistent with W6.0's measured capability surface.
