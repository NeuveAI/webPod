### Proposed bounded correction and verification

1. **First slice: native gesture ownership**, `device-native-input.ts` only, plus a narrow typed ownership signal if necessary. Record a successfully admitted enclosure pointer and skip only its hover re-query until up/cancel/lost capture/dispose. Keep the existing app capture listener as sole trajectory/final-sample owner. Do not skip initial down, active clickwheel/Select queries, free hover or another pointer's admission. Prove capture failure, rejected begin, blur, owner replacement and reentrant cancellation cannot leave hover suppressed. A real accepted orientation gesture should have one initial admission query and zero redundant hover queries, while immediate public orientation and pointerup final sample remain unchanged.
2. **Second slice: query publication**, `device-query-view.ts` with its native adapter caller. Cache immutable local-chain products and dirty only affected wheel/Select chains; model/content pose changes still update all necessary world matrices synchronously. Expose an explicit current-query synchronization boundary instead of unconditional recursive input traversal. Mutation revisions must cover native proxies, equipped children, control frames and same-turn external writes; no pose-only cache without those dependencies. Preserve exact matrix results and query identity. Keep registered external/unrecognized mutation fallback defensive. Remove duplicate control publication only after proving the caller already owns the same pose/version.
3. **Attribution before further optimization:** a bounded production probe should separate ancestor audio activation, native sample/matrix synchronization, shell/proxy raycast (including indexed versus fallback status and candidates), accepted-begin work, and public-store/intent subscriber dispatch. Count work without retaining buffers or per-frame unbounded logs. Repeat matched cold-first-down and already-activated down, plus the same trusted front→rear drag. The current observer cannot distinguish index fallback, audio cold cost, subscription work or JIT warmup. Do not infer a GPU bottleneck from these main callback durations.
