W2 — the store is readable, writable and subscribable from OUTSIDE REACT
========================================================================

The property: device state lives in a Jotai `createStore()` and is reachable
through `store.get` / `store.set` / `store.sub` with NO React tree mounted.
Tool callbacks live outside the React tree and must read and write the same
state the UI renders; state held in a component closure is unreachable from
one.

⚑ The review narrowed this claim correctly, and the narrowing is now closed —
in two rounds, because the first attempt was wrong.

Proving the package does not *need* React is not the same as proving a tool
callback and the UI address the same device: nothing stopped a consumer from
handing its `Provider` a fresh `createDeviceStore()`. Two stores, both valid,
both React-free, every test green, and the tools moving a screen nobody is
looking at.

The first fix counted constructions and threw above one — but the singleton is
built through a private path that did not increment the counter, so the FIRST
production call succeeded, which is the only call the motivating case makes.
Its test was green because 25 earlier calls in the same file had pushed the
counter past the threshold.

Now: `createDeviceStore` throws whenever it is not under a test runner, on the
first call and every call; it is not reachable from `@webpod/state` at all,
only from `@webpod/state/testing`; `index.ts` enumerates rather than
re-exporting `./store`, so it cannot creep back; and the first-call test runs
in a fresh subprocess with a fresh module registry, where nothing this file did
can make it pass.
