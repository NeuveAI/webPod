## Native snapshot transfer probe

Bounded five-second probe captures the existing panel during paint and transfers only the ElementImage to a temporary worker; no live canvas transfer or context replacement. Worker and snapshot resources are closed and listeners/timeouts removed in cleanup. First draw attempt used an options overload absent from installed Chrome 152.0.7977.83 and failed overload resolution. Correct five-argument retry reached drawElementImage but failed InvalidStateError: source captured from a different canvas. Both returned unchanged presentation canvas dimensions and unchanged panel transform. This disproves the detached staging-canvas route in the current browser; it does not disprove direct texture upload from a snapshot associated with the transferred presentation canvas. The latter remains to be established before implementation selection.

The subsequent associated-canvas contract probe PASSED through the current Chrome MCP. A temporary diagnostic canvas was transferred before context acquisition; worker WebGPU adapter/device initialized, main captured its solid native DOM child on paint and transferred ElementImage, worker copied via copyElementImageToTexture to rgba8unorm. Source and texture were both 64 x 32. A validation-only GPU row readback returned exact center pixel [100,150,200,255], matching the solid child; validation scope returned no error. Cleanup removed the temporary canvas and worker/device/texture/buffer resources. The live player canvas was untouched. This establishes the native associated-canvas upload contract only, not full LCD/shader/hit parity or speedup. Implementation must preserve that association and transfer before renderer context creation.
