## Decisions

1. `deviceStore` is the sole store. The route mounts two Providers over that same store so the colourways remain synchronized and tool callbacks observe the rendered state.
2. Panel internals remain exactly 272×204. The owner preview uses integer page zoom; Dynamic Type scales only the bounded panel stage and is capped at 1.25.
3. Unsupported capabilities are absent from the model, never disabled controls. Radio is therefore absent from S03 under the launch matrix.
4. S08 uses TanStack Virtual when the fixture exceeds 100 rows. The test fixture contains 120 rows, while loading remains exactly eight 26px rows. A browser measurement records 60 animation frames under 4× CPU throttling and separately bounds the mounted row count.
5. After coordination approval, the route consumes canonical `@webpod/panel`; the app manifest and lockfile preserve the device/composite lane dependencies already present.
6. HTML-in-canvas, device materials, and composite transforms are outside this package. The panel is independently focusable semantic DOM.
7. H-6 and U14 require owner observation and remain explicitly open.
8. W5a implemented the universal runner. Its command phases (types, lint, and tests) pass, including root Bun discovery after the browser-test suffix moved to `.e2e.ts`. The latest rerun is presently blocked before those phases by a concurrent, W5a-owned deletion of `scripts/gate-core.ts`; W3 neither restores nor commits that foreign file. Earlier W5a static failures were acknowledged false positives under W5a review, so truthful prescribed state names remain intact.
9. Browser evidence is locator-cropped at 544×408: exactly 2× the 272×204 raster, without page chrome. Overview captures remain only as navigation aids.
10. The adaptive artwork fixtures are deterministic visual inputs: pale and dark surfaces pair with exact 3×3 dominant-colour and 8×8 luminance samples. Provider artwork remains the normal non-fixture path; the fixture surfaces make all four adaptive branches independently inspectable.
11. The panel package contains no CSS blend or filter effect. Artwork ambience is a pre-composited radial colour field made from raster-safe gradients and custom properties; scanline/sub-pixel treatment remains the screen-mesh shader’s responsibility. This preserves the bare-DOM colourway treatment without importing composite, branching on tier, or duplicating the shader overlay. Reduced transparency removes the ambience entirely at the same package seam.
