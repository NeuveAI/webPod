## Identity and cache behavior

A first build uncovered separate Vite config evaluations for client and server; a module-scoped UUID was insufficient. Corrected before review: apps/web/scripts/build.ts creates one random UUID per build invocation and supplies it to the child Bun/Vite process. The app build script delegates to this launcher; root `bun run build` and Dockerfile.vercel also delegate through it. Supervisor approved this necessary manifest/launcher scope expansion. Vite validates the value and throws a clear “use bun run build” diagnostic for direct unscoped Vite builds. Nothing persists between build invocations. No commit SHA dependence, source scanning, secret or environmental data goes into the public identity.

`APP_BUILD_ID` is compiled identically into browser and Start modules. `/api/version` is a canonical Start file GET route, returning only `{buildId}` with cache-control:no-store and cdn-cache-control:no-store. Start HTML gets no-cache,max-age=0,must-revalidate and cdn-cache-control:no-store; static/hash-addressed assets remain unaffected. Dev's identity is “development” and the monitor stays quiet. The generated route tree is regenerated by the normal build.

## Browser lifetime and UI

Jotai owns latest deployment, page-session dismissed identities and reload state. One ref-counted mounted root monitor owns one QueryClient and one timer. Query fetches have zero staleness, no retries, explicit networkMode always (offline admission is checked separately), 5-second abort deadline, no-store request and strict UUID validation. Checks happen on visible mount, foreground, online and every 60 seconds while visible/online. A request in progress admits at most one queued check; visibility/offline cleanup aborts it. Unmount cancels query, request, timeout, interval and listeners. Malformed, failed and offline checks announce nothing; valid prior notices can remain until dismissed.

The nonmodal safe-area-aware notice does not steal focus or touch playback. It uses polite live text, “A new version is ready”, “Reloading pauses playback.” and 44px-minimum Later/Reload buttons. Later dismisses that exact identity for this document lifetime; another identity can announce. Reload is explicit, guarded against duplicate activation, replaces one bounded `_webpod_version` query value and preserves path, other query parameters, hash and all local saved data. It does not clear caches/storage or automatically reload while playing or manipulating stickers. At 390×844 it sits below the device; at 320×568 it overlaps only the lower plain shell, leaving clickwheel buttons visible. Screenshots in evidence/update.
