# D6 diary — playback error presentation

**Date:** 2026-09-04
**Implementer:** `/root/d2_aqua_visual`
**Status:** implementation and evidence complete; independent review pending

## Context and critique

The authorized Apple replay kept the correct song, artist, album, artwork, source, queue position, and duration after playback failed. The presentation obscured that success: a long absolutely positioned error sentence occupied the same final LCD row as five transport-status glyphs. The development diagnostic then described the later paused event as “Latest” and showed no error class, even though the bounded trace already contained the causal media failure and audio error.

The target hierarchy is now song identity → playback status → recovery guidance → technical trace. The 272×204 LCD remains the music surface; browser-specific investigation stays in the development-only panel.

## Implementation decisions

- Replaced `.wp-state-note` with a 25px grid-owned `.wp-status-shelf`. The final Now Playing row renders either the five normal actions or one status shelf, never both.
- Kept artwork, title, artist, album, source, queue position, progress, and times mounted when provider playback fails.
- Used an outlined symbol plus a short label for pending, failure, subscription, offline, agent, and success states. The failure copy is the intentionally generic `Playback unavailable`; it does not promise that retry can repair a protected-media incompatibility.
- Kept the shelf on the existing grid rather than introducing a toast, modal, or absolute overlay. Reduced-transparency and forced-colour branches provide solid backgrounds and system-colour outlines.
- Added a typed diagnosis derived from the full bounded safe event snapshot. The live failure shape—EME unavailable, audio code 4, `mediaPlaybackError`, then paused/none—retains the media error as its causal event after later state notifications.
- Preserved separate autoplay, network, decode/source, DRM/entitlement, and unknown diagnoses without carrying raw errors, URLs, tokens, item identifiers, license data, or media keys into the snapshot or UI.
- Moved the sanitized state table and event list behind `details`; the always-visible header contains one plain-language cause and one next action. Only that stable summary is a polite live region. Causal and latest-follow-up events have separate labels in the disclosed timeline.
- Added `Retry Apple Music` only when the requested provider is Apple and the runtime is in its error phase. It invokes the existing Apple selection path directly, retains `Use demo library`, and does not claim that an existing session needs sign-in.
- Preserved the compact desktop control density while giving the recovery action a 44px minimum touch target at the mobile breakpoint.
