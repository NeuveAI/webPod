# Startup gate diagnosis

The original `evidence/session-restoration/reviewer/startup.log` contains two different failures. The root launcher passed initial readiness, both real routes, server/client boundaries, CSS HMR and both configuration-header assertions. It failed only when the test explicitly navigated after changing the config helper. The app launcher timed out before initial readiness; its log retained no phase or process sample beyond the launch command.

Pinned Vite 8.2.2 is the relevant source. The local reference checkout is Vite 7.2.7 and differs. In installed `dist/node/chunks/node.js`, `restartServer` creates a replacement server, closes the old server and listens again. In installed `dist/client/client.mjs` around lines 1000–1009, the client handles websocket disconnect by waiting for a successful ping and then calling `location.reload()`. Therefore a successful HTTP header probe does not mean the browser's independent reload has completed. The test's final `page.goto` can race it and produce `net::ERR_ABORTED`. This mechanism matches the exact failed line; it is not an application error suppression rationale.

One isolated app-launcher rerun, with unchanged source and timeouts, passed all 1023 assertions in 55.96 seconds. It included both routes and CSS/config/helper reload checks. Its log is `startup-app-isolated.log`. During that run an owned-process macOS sample showed active Tailwind scanner/Rolldown work; `startup-app-process-sample.txt` retains it. This is not a sample of the original timed-out process. The original initial-readiness timeout is not reproduced or conclusively attributed to contention. No runtime, launcher, timeout, credential or environment changes were made to address it.

The first correction attempted to wait for an automatic main-frame reload response with the new helper marker. A combined run falsified that assumption: the root launcher timed out at initial readiness, and the app launcher reached the helper update but no qualifying automatic navigation arrived within 15 seconds. `startup-synchronized.log` preserves both failures. That implementation was replaced, not accepted.

The final narrow correction owns only `apps/web/scripts/dev-startup.integration.test.ts`. It retains the explicit post-helper navigation and retries it once only when Playwright reports `net::ERR_ABORTED`. All other errors propagate, and a second abort is fatal. The final document must return 200 and satisfy the existing T1 render and browser/server error assertions. No sleep or timeout increase is added. This handles Vite's optional concurrent reconnect reload without requiring it to happen.

A subsequent root-only diagnostic run passed all 1024 assertions in 54.26 seconds (`startup-root-diagnostic.log`). An owned-process sample taken during that run found the server already listening, mostly in idle waits; a direct anonymous `/@vite/client` diagnostic returned 200 with 205095 bytes in 4.95 ms. This run did not reproduce the initial-readiness stall. Its sample is not evidence for the cause of the earlier failure. The intermittent 45-second initial-readiness failures remain unattributed; neither evidence growth nor session-runtime code is established as their cause. The snapshot helper excludes the entire docs tree, falsifying workstream evidence growth as a direct scanner input for these tests.

Scoped ESLint and application typecheck pass. Independent combined canonical validation remains the acceptance gate; no repeated-until-green claim is made.

The test host remains credential-free and isolated; no user server or browser was touched. The final combined startup validation and independent review are recorded separately after this diagnosis.
