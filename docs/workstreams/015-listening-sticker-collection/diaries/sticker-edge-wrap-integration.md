## Runtime budget and ownership for a future physical-sheet solver

This is an integration proposal, not a performance claim. Current2–10second cold solves are disqualifying for direct manipulation. Moving that work to a worker only frees the main thread; it does not make a multi-second response follow the pointer or keep the HUD and physical print aligned.

**Current synchronous boundary.** EquippedSticker memoizes createStickerSurfaceGeometry by art/placement/rear geometry; a changed draft therefore blocks React until geometry exists. PeelingPrint constructs source and target geometry again inside its layout effect as peel/landing changes. A slow physical solve must never be inserted into either path, pointermove, contour projection or hit testing. Existing WebMCP animationGeneration guards deliberately recheck ownership after each store publication and before completion/RAF scheduling. Preserve them and extend the same generation discipline to solver publication; do not let a late solve clear a newer peel or trigger a stale autosave.

**Smallest proposed runtime API.** Geometry owns a session-scoped prepared solver resource keyed by immutable shell/collider revision, artwork UV/topology and initial valid placement. A candidate interface is `prepare(input, signal) -> resource`; `resource.update(target, generation, budget) -> readyFrame | pending`; `resource.subscribe(onReadyFrame)` only if work is asynchronous; and `resource.dispose()`. Each readyFrame carries its exact placement, request generation, geometry version, positions/normals/UV references and quality result. The resource owns at most one active and one latest requested target, coalescing intermediate pointer moves. Cancellation/abort/dispose stops computation and callback delivery; it does not merely ignore results while leaving an unbounded worker queue running. Avoid exposing solver internals to Jotai or serializing them into placement records.

**Direct interaction requirement.** Pointer sample and HUD active grip update synchronously. A physically valid visible mesh for the same target must follow by the next admitted animation frame, using bounded warm-start work from the previous solution. Last-valid-cache retention prevents disappearance on failure but is not proof of direct tracking: a frozen sticker with a moving HUD fails. A simple screen-space translation of an old wrapped mesh is also invalid when it floats off the shell. If the solver cannot provide a valid warm update within the measured frame budget, it is not ready for this product workflow; do not hide the limitation behind worker latency, stale graphics or a spring that trails input.

**Provisional measurable budget.** On the existing60Hz fixture, reserve no more than4ms main-thread CPU for geometry publication/upload and projection per gesture frame, leaving room for lighting/render/input; report actual distribution rather than calling this guaranteed. Target pointer-to-visible-frame p95 within one16.7ms frame, no repeated gaps over33ms and no interaction-window tasks/LoAFs≥50ms. Measure cold preparation separately, including its first valid visible geometry and total convergence, not only warm cache. Cold work must be bounded/cancellable and must not clear previously visible owned stickers;2–10seconds remains a failed admission result. The final acceptable cold deadline must be demonstrated with the actual shell/artwork and total ready-to-use latency, not selected from an abstract solver benchmark.

**One published physical frame.** On the render thread, swap the ready geometry, its contour/hit acceleration data and its exact rendered-placement version together before invalidation. Front and adhesive back borrow the same frame; hit/contour never describe a newer target than the shown print. Draft intent may be newer, but cannot masquerade as rendered/saved placement. Release waits only a bounded final-quality result for that exact target/generation, then dispatches the existing expected-source/revision write. If convergence fails or exceeds that bound, restore the original canonical placement with contextual recovery; never silently save a different cached target. Unknown persistence,409 reconciliation and session invalidation remain owned by the existing app runtime. A stale solver result must not retry persistence or publish old ownership.

**Peel ownership.** Prepare the static contact solution once for the exact source/destination placement. Peeling/pressing derives its time-varying contact mesh from that prepared solution with bounded local deformation; it must not run a global relaxation for every spring tick. Use compatible vertex/UV topology and carry a retained frame lease through lift/press/return, releasing on completion/cancel. Solver cancellation and animation cancellation are separate resources under the same gesture/session generation, so releasing one cannot orphan the other.

**Cache and memory bounds.** One immutable collider per shell revision; at most the currently rendered placements plus the active carried source and latest target solution, never an unbounded placement-angle cache. Reuse fixed-size typed arrays where possible. Old geometry/worker buffers are released only after the replacement frame no longer references them. Wear is a material update and must not invalidate shape preparation. Pose-only device rotation should update projection, not solve geometry again. Logout/provider replacement invalidates pending per-session work; immutable artwork/collider data may remain shared only without owner-specific placement state.

**Required performance evidence before integration acceptance.** Instrument actual pointer input, published geometry version/placement, buffer upload, render callback, queue length and cancellation completion from test-owned probes or browser profiling. Include cold first wrap, continuous edge-to-corner movement, rapid reverse/rotation, release while a solve is pending, lost capture, immediate re-grab, hidden/resize and session change. Positive draw/update controls must prove instrumentation is live; settled idle then shows no perpetual solver/RAF/draw loop. Assert stale generations never publish, only the latest request remains queued, shown mesh/hit/contour versions agree, and the persisted placement equals the released target. Tests of a worker Promise alone cannot establish these properties.

No source changes or heavy runs were made for this proposal. Geometry owns solver preparation/work/disposal and rendered-frame validity. App owns gesture generations, intent, cancellation and revisioned persistence; device render glue owns atomic frame publication. Final signatures and budgets await an actually responsive physical candidate and independent review.
