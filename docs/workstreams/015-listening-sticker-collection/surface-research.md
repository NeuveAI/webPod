## Geometry and ownership

`ProductionDeviceView → CompositeDevice → DeviceCanvas → Device → ViewerLitDeviceFrame` is the production chain. Thread only serializable placement/catalogue props through the first three. Mount sticker meshes inside the Device-owned ViewerLitDeviceFrame children, underneath `device-model-content`; Canvas children are siblings and do not inherit the iPod transform. World-fixed key/kick/rim lights remain outside `device-model`.

Crucial distinction: the rear cap is FLAT at `-depth/2`, with normal `(0,0,-1)`. `createRearShellGeometry` in `product-shell.ts` builds a quarter-ellipse sweep of superellipse plan rings around that cap, not the front's vertical/cross crown. Applying `verticalCrownOffset` to rear stickers would detach them from the real shell.

Recommended surface algorithm: construct a modestly tessellated sticker grid in device XY; convert visible artwork bounds to intended body width without stretching the intrinsic ratio; rotate placement in rear-view coordinates (rear view reverses model X). Project each vertex from behind the device toward +Z onto the actual rear geometry, interpolate its mesh normal and add a small outward model-unit lift. This conforms to cap and rolled shoulders using precisely the rendered source geometry. Reject occupied silhouette points with no rear hit rather than bridging the perimeter. Triangle clipping is preferable if arbitrary edge wrapping is allowed; a bounded placement zone wholly within the rear cap is a legitimate initial product constraint, but must be explicit and must reject out-of-zone writes. A plain oversized rectangle laid over the rolled edge is not acceptable.

Store stable IDs, placement position/size/rotation, selected pack, interaction stage and preview through the one `deviceStore`. Follow public read atoms + action atoms with validation, and re-export through state/index.ts. GPU maps and geometries are owned runtime resources, never persisted values. `faceAtom` alone is insufficient as a continuously resolved geometry predicate; use the actual orientation/visible-face resolver to gate rear interaction, with hysteresis or rest-state admission so a mid-flip back crossing does not repeatedly reveal a pack.

## One physical laminate

Use one `MeshPhysicalMaterial` per sticker mesh with shared named material recipe: metalness 0, base roughness about .58, clearcoat about .3, clearcoat roughness about .35; tune dark/bright/ivory examples together in existing light rig. These are initial calibration values, not acceptance evidence. Put recipe in materials.ts (or a clearly named sticker material table exported beside it), not genre literals.

The installed `meshphysical.glsl.js` executes map/alpha-map/alpha-test before physical lighting and clearcoat accumulation. Its map chunk multiplies RGBA; `alphaMap` reads GREEN, so do not supply the original RGBA PNG as an alphaMap and assume its alpha channel is used. Prefer the PNG as map, with alphaTest `16/255`, transparent true, depthWrite false, minimal normal lift and tested ordering. This single discard gates both print and coat, including near-zero margin residue. Preserve genuine edge antialiasing above the threshold. Consider alphaToCoverage only after visual MSAA verification; installed shader uses a threshold/smoothstep derivative and is not identical to conventional alpha blending.

Set printed color texture `SRGBColorSpace`. Generated roughness textures remain non-color data, deterministic and low amplitude. Use a shared physical scale, no oscillating noise and no alternate artwork with baked highlights. Avoid a second clearcoat shell unless evidence proves it is required: it adds alpha synchronization, depth sorting and ownership hazards. Reuse production environment; clearcoat should respond to rotation and stop at rest.

Explicit resource ownership: cache immutable source color textures and shared microtexture with reference counting or a parent-owned lifetime; dispose per-placement geometry/material only once. R3F primitive objects are not automatically disposed, as confirmed by its installed reconciler. Never let removing one sticker dispose a shared map still used by another. Cancel/ignore late loader results after unmount, invalidate after completion and handle image errors visibly. The current DeviceCanvas demand loop must remain demand-driven; no continuous sheen loop.

## Interaction architecture and alternatives

Considered (1) a generic inventory sheet, (2) a physical pack integrated into the existing scene with semantic DOM controls, and (3) an independent full-screen opening sequence. Choose (2): it preserves contact with the rear device, supports the requested bottom tease, and lets laminate use the actual rig. The inventory sheet is useful only as accessible fallback; a separate takeover would remove spatial continuity.

A module-level state machine should own `hidden → tease → pulling → open → peeling → placing → settling`, plus explicit cancellation. Named spring/geometry constants and an ASCII storyboard describe the phases. The bottom pack exposes an actual 44px semantic Open pack button even when only the lip is visible. Drag upward directly controls progress; estimate release velocity from recent samples and resolve an open/close spring with bounded inertia. Existing device-orientation-motion.ts provides tested reference logic for rejecting stale/nonmonotonic/implausible velocity, and for spring termination and reduced motion. Reuse shared math only where units and behavior truly match.

The pack needs modeled laminate under the same rig; a CSS sheen on a production 3D pack would not match the device's light response. Pack pull position is screen-anchored until opening, while equipped stickers live in model coordinates. Define the world/screen conversion explicitly rather than guessing CSS pixels as body units. Use a tessellated peel mesh whose local bend/curl is driven by peel progress; landing interpolates into the projected surface with bounded spring overshoot and maintained velocity. This is a purposeful 3D deformation, an explicit interpretation of the user's physics requirement beyond Neuve's general DOM transform-only rule. Do not claim realistic peel if implementation merely scales a flat thumbnail.

Handle pointer capture, cancellation, lost capture, Escape, front flip and sign-out. Sticker gestures must not also start orientation grabs. Filter hit tests with the same threshold-16 alpha in the same UV transform; transparent holes/corners pass through. Keyboard/button actions must open, select, apply and remove without requiring precision dragging; meaningful announcements describe success/error. Visible status must distinguish loading/empty/offline/error/earned inventory. Reduced motion snaps physical stages to their stable result and retains direct manipulation, labels, focus and actions. Kill all RAF/timers/subscriptions on settle and unmount.

Apply guardrails contextually: retain existing webPod typeface and compact physical-device layout; Neuve brand/iOS-only/120px marketing-section advice is not this product's brand. Physical light gradients are required laminate rendering, not decorative interface gradients. No edge rails, no hover-only controls, no generic dashboard card grid.
