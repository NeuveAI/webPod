### Findings

- **[MAJOR B1] Importing an already-enriched song never marks it as library evidence** (`packages/server-core/src/stickers/repository.ts:50`). The conflict update changes genre/duration but preserves `source='catalog'`, while line 51 excludes catalogue rows from starter taste. Trigger: active-track enrichment records a song before a later successful/retried library import contains that same song. Repeated imports cannot repair provenance; a complete one-song rock library reproducibly returns zero starter packs. Mixed libraries also rank genres incorrectly. This violates D2's genre-based starter and D3's provenance requirement. Merge library membership on conflict (or model provenance independently) and cover enrich → import → repeated import, including a partial snapshot followed by completion.

- **[MAJOR B2] A late starter can award artwork already earned through listening** (`packages/server-core/src/stickers/repository.ts:52–53`). Starter contents always select each genre's first sticker without checking existing ownership. Trigger: library import is empty/failed/unclassified, listening later earns rock's first sticker, and a successful import adds a different rock song. The probe produces two distinct packs both containing `PW-C01`; opening the later pack reveals no new sticker. The listening path already filters owned art at lines 90–93, but starter does not, and distinct grant keys allow the duplicate. Preserve the one-starter contract while selecting only eligible unowned contents (and define the all-owned case), with a deterministic late-import retry regression test. This concerns distinct grant paths, not a request for different earning thresholds.

- **[MAJOR B3] Imported incomplete metadata permanently blocks catalogue enrichment and listening rewards** (`packages/server-core/src/stickers/repository.ts:61–66`, `packages/server-core/src/stickers/http.ts:65`). `hasTrack` treats a row with `genre=null` as fully resolved, so HTTP never enriches it; even an explicit `enrichTrack` call discards corrected metadata via onConflictDoNothing. Trigger: a valid imported song lacks a supported library genre while catalogue metadata can resolve one. The probe imports null genre, explicitly enriches the same song as rock, observes ten valid seconds, and still gets zero rock credit. Retrying import with weaker/null metadata can also overwrite a previously resolved genre at line 50. Unknown genres should remain unknown when authoritative enrichment is unknown, but missing library metadata must not suppress available catalogue evidence. Track resolution/provenance explicitly, permit bounded enrichment when needed, and merge stronger metadata without erasing library membership; test null → resolved, resolved → weaker import and truly unknown without a repeated network loop.

- **[MINOR B4] Unknown genre strings can resolve inherited object properties** (`packages/server-core/src/stickers/policy.ts:20`). `aliases[name]` on a normal object returns a function for `constructor` and an object for `__proto__`; independent probes confirmed both instead of null. This breaks the declared StickerGenre/null boundary and can cause a safe-but-unnecessary storage failure. Use own-property lookup or a Map and test inherited-key names.

### Suggestions and remaining verification (non-blocking for this neutral lane)

- `openPack` reads and writes openedAt outside a transaction (`repository.ts:102–104`). One shared synchronous Bun runtime serializes this locally, but independent database connections can overwrite the first opening timestamp after both read null. Use a conditional SQL update/coalesce or an immediate transaction before claiming cross-process opening idempotence.
- Apple import currently discards every completed page when a later request fails; `partial` only means a hard page/track cap. Document that all-or-nothing retry posture or preserve validated partial results with explicit failure provenance. Add tests for 429/later-page failures, repeated next paths, malformed pages, byte caps and terminal capped snapshots before integrated ingestion approval.
- `sticker_schema` is currently a v1 initialization marker rather than a migration runner; make future-version rejection and additive upgrades explicit before a v2 exists. Actual SQL indexes absent from Drizzle table definitions should stay synchronized if schema generation is adopted.
- No auth/runtime routes exist yet, so forged/expired sessions, revocation during import/enrichment, caller abort propagation, origin behind production proxy, active stream lifecycle, bounded network concurrency/rate limiting and production client secret isolation must be exercised by the next review. Neutral tests must not be reported as proof of those deferred boundaries.
