## Identity contract
Use a cryptographically random first-party device credential persisted for this browser, mapped server-side to an opaque collection owner. This provides the requested temporary device identity without relying on unstable hardware/browser attributes. Device identity survives reload and MusicKit sign-out/reconnect in the same browser profile; clearing site storage or using another browser creates a new collection. Different Apple accounts used in the same browser share this device collection by design for this interim release. No claim of Apple account matching or cross-device restoration. Stable future accounts can link the existing opaque owner through an identity mapping without rewriting inventory/grants.

Store only hashed device/session secrets in SQLite. Prefer HttpOnly, SameSite=Lax, path=/ cookies and Secure on HTTPS; no sensitive credential in URL/public Jotai/domain Session/logs. The device credential permits recovery after newly verified MusicKit authorization, not signed-out inventory access. Issue a separate expiring active session; logout revokes active access and pending bootstrap work while retaining restricted device identity. Explicit bounded TTLs/configuration and generation/revocation checks prevent old imports or enrichment from mutating a signed-out collection. Account switch semantics are device-based and documented. Do not persist Music User Tokens; catalogue enrichment can use server developer token and stored verified storefront without Music User Token. Upstream verification and personalized import retain the token request-locally only.
