## Lifecycle, cancellation and failure inventory

- **Immutable shell preparation:** session-wide one worker, one active plus three waiting forms. Same-form cache shares geometry; four unused completed pairs and30s idle retention, live owner refcounts; last owner removes/disposes. Suspended/discarded renders still finish their bounded job and expire later.5s worker deadline. **Hazard:** worker error/timeout falls back to `setTimeout(() => createImmutableShells(form,false),0)`. The callback performs the entire original constructor synchronously; scheduling one timer does not make hundreds of milliseconds of numerical work cooperative. Background/abandoned jobs are not cancelled until completion. A broad architecture must eliminate this monolithic fallback or provide a justified supported-browser failure policy without a quality downgrade.
- **Shell picking preparation:** one global worker, four waiting jobs,15s deadline; cancellation terminates active worker and restarts queued work, idle terminates. Busy/error retains original exact full-triangle main raycast. Correctness is preserved, but fallback can put the original large query cost back onto input. Prepare query data with geometry before interactive readiness and retain a usable prior query snapshot on compatible refresh; failure must not silently promise fast input.
- **Paper CPU fallback:** shared pool, at most32 owners, one pending job per owner/FIFO; owner lifetime cancels waiting/active work, pool stops when no clients. Per-owner preparation sets a10s deadline; queue wait can consume it. A timeout may therefore initiate cooperative CPU recovery even though the worker is merely servicing another owner. Multiple owners can recover concurrently. Execution budget and queue admission should belong to one broker, with queue starvation distinguished from actual worker failure.
- **Collision:** current StickerPackScene owns **one** visibility instance shared with carry, not two (older audit counts are superseded). Each preparation creates a transient worker,15s deadline; abort terminates and does not retry; failure invokes cooperative builder. Its numeric assembly signature still traverses all scene descendants/ancestors per inspection. PeelingPrint recursively updates world matrices and inspect immediately does so again. Immutable snapshot caching removes repeated serializeNode allocation, not these traversals or copy/restore work.
- **Carry:** one worker per active device, one active+latest pending job,15s deadline. Hidden/unmount stop work; current intent resumes when visible. Epoch and worker-instance guards reject obsolete poses; compatible completed poses publish to avoid continuous-input starvation. Immutable wear revisions now preserve resource identity; cached/displayed/retired leases dispose after commit. Renderer context loss is not the same thing as gesture epoch or document visibility—asset/upload acknowledgements need an explicit rendering generation in a worker renderer architecture.
- **Cooperative algorithms:** yieldSteps schedules an initial timer, then checks a4ms budget between generator steps. It cannot preempt a native sort, typed allocation, computeVertexNormals/bounds, geometry clone or overly large step. Independent concurrent fallback generators each get their own budget, so aggregate main-thread work can still crowd input. A shared cooperative scheduler and finer pure loops are required for a real UI-priority fallback contract.
- **Entry/physics:** device-reveal publishes the original logical curve through the main store;32ms step clamp can stretch physical duration under slow frames. ControlPhysicsController requests frames only while moving. DeviceRenderWarmup starts only after full scene commit and reports failed after10s compile timeout, suppressing late completion. Keep authored trajectory and input interruption semantics; optimize execution ownership rather than shortening/removing animation.

Worker concurrency is bounded per subsystem, not by one session-wide CPU budget: shell construction, shell indexing, paper and per-device carry/collision can overlap. Multiple device copies multiply carry/collision workers. A shared geometry/compute broker should schedule finite work globally; moving rendering to a worker must not simply add another permanent worker to an already oversubscribed pipeline.

## Proposed disjoint implementation slices

### A. Complete immutable scene preparation and exact recovery

Own new preparation protocol/broker and pure factory/raster modules, immutable-shell preparation, Device construction adapters and DeviceHardware. Do not own scene renderer, screen transport or sticker interaction state.

Make a versioned prepared assembly contain front/rear/control/hardware/display geometry, exact finish texels, metadata and query-index inputs. Construct once in a shared preparation worker, transfer owned immutable buffers before scene readiness and reuse by complete form/texture recipe key. Keep renderer materials and context resources owned by renderer; workers emit data, not serialized Three instances. Canvas-dependent label/engraving raster gets an explicit worker-compatible adapter only after exact image/text parity. If GPU texture generation is selected, preserve integer PRNG results, channel rounding, sampler settings, color space and mip behavior; per-fragment procedural approximation is not equivalent.

Replace the monolithic shell fallback with the same pure pipeline expressed in budgeted stages, including native-heavy normals/triangulation stages or a separately justified compatibility gate. A timer around the old function is not an acceptable final fix. Broker enforces bounded queued bytes/jobs, latest-per-owner work, cancellation, idle release and execution-start deadlines. Audit all private buffers on abort; do not detach a displayed/shared cache buffer.

Gates: exact expanded triangle attributes/groups/order and texture pixels versus current pipeline, ownership across multiple identical forms/StrictMode/discarded renders, failure/timeout/hidden cancellation, no resource swap after warm-ready, baseline versus new main-thread long tasks during cold entry.

### B. Packed collision/query authority and stable assembly revisions

Own sticker-collision/visibility/preparation, shell candidate-index transfer and read-only query adapters. Depend on A's asset IDs, not on renderer migration.

Keep immutable triangle/BVH data in typed packed arrays created alongside preparation. Avoid restoring tens of thousands of Box3/Vector3 objects on main and later cloning nested trees to carry. Hand carry the same versioned prepared representation via direct worker messaging or explicit private transferable copies. SharedArrayBuffer is only an optional path after cross-origin-isolation capability is verified; it is not a default assumption.

Main receives a compact immutable query view for immediate exact admission and a current pose/camera transform. Preserve UV/material-side/face/provenance semantics and wrapped sticker priorities. Replace repeated scene traversal with explicit assembly revision publication at geometry, material visibility and local-transform mutation owners; globally rotating the device must not rebuild local collision geometry. Retain enough exact print geometry/index data to accelerate sticker queries as well as shell queries.

Gates: existing exact shell840-ray/contact/provenance suites plus dense sticker alpha/occlusion tests, no stale local physics transforms, replacement/error/cancellation parity, measured first-pick and steady-pick call/byte counts. The old snapshot cache remains useful and must not regress.

### C. Transactional sticker geometry, damage and release work

Own equipped-sticker preparation, surface damage/contour preparation, drop fitting and carry persistent-resource protocol. Do not edit main renderer/Canvas or device pose authority.

Move saved-placement/editor dense geometry into the same bounded compute service, keyed to art/placement/form revisions. Perform release fitting as an owned transaction: preserve final pointer sample and show the existing carried pose while exact fit computes; only the current generation may save/place. Preserve duplicate-command protection and user cancellation. Precompute/cache immutable damage fields with source resources; contour/visible bounds can use worker-prepared structure with current-camera projection of only required points on main, or asynchronous exact results guarded by committed geometry+camera revision. Measure before allowing large contour sampling to remain main.

For GPU preference, carry contact/deformation may become compute-shader work only when its exact collision/material constraints and editor/hit consumers have a coherent representation without synchronous full-buffer readback. This is a substantial numerical-parity slice, not a casual shader port. Existing full-resolution worker algorithms remain the equivalent fallback. Do not reduce96×96 topology or omit contact constraints to claim a GPU path.

Gates: former effect/worker/GPU or cooperative byte/numerical parity with explicit tolerance only if visual equivalence permits it, source-target wear identity, final release/save semantics, no outdated pose/contour after gesture changes, failure restores usable state, sustained gesture traces and memory/upload counts.

### D. Main UI authority with lean pose/animation publication

Own device-preview-orientation, device-reveal, ControlPhysicsController, production scene prop memoization and a typed render bridge. Renderer worker integration itself remains WEBPOD-CPU-004's follow-on.

Main handles DOM events, media/user activation, immediate tool-readable Jotai state and essential admission. Publish latest device/camera/control transforms once per visual frame through stable typed records; retain ordered start/release/cancel/command messages with acknowledgements. Do not coalesce away final pointer samples or tool commands. A render worker may animate autonomously between semantic commands only if the main public state stays coherent and user interruption/final pose timing match the existing curve. Separate frequently changing pose from immutable React scene descriptions, rather than rebuilding the whole production subtree for each angle.

Gates: identical authored entry/inertia/control trajectories and clamps; same-turn public state; ordered final release and interruption; no extra stale DOM hit frame; demand-loop idle behavior; context-loss epoch rejects stale frames/resource acknowledgements. Main-thread DOM projection remains a browser requirement; duplicate scene/matrix/diagnostic work does not.

## Renderer coordination and overall acceptance

A–C can remove substantial main-thread preparation and interaction barriers even if the DOM LCD prevents immediate whole-renderer worker migration. They are not a substitute for completing the renderer compatibility decision. Prefer compatible GPU/WebGPU rendering and worker submission; if current native HTML display cannot cross that boundary, document the exact browser/API constraint and use the strongest equivalent GPU/worker path without a placeholder or lower fidelity.

Installed Three0.185.1/Fiber9.7.0 sources are authoritative; the local resource catalog has no matching Three/Fiber reference checkout. Verified Fiber render-loop source executes gl.render on its host thread, and verified Three ImageBitmapLoader calls createImageBitmap with explicit color-space options. No invented WebGPU/OffscreenCanvas adapter is prescribed. Lead's renderer audit must settle canonical API, custom shaders, DOM-screen transport and context recovery before that implementation is accepted.

Completion requires independent review and real current-Chrome entrance/rotation/peel/carry/stick/clickwheel/playback checks, a recovered context-loss path, and bounded6× before/after traces with DEV/production provenance. Existing historical geometry/picking/parity results establish correctness baselines, not a new frame-time gain. Current main work listed above is source-proven; priority and latency require measurement. The complete architecture goal remains active beyond this audit.
