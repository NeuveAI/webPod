## Stable contracts

- physical-material-nodes.ts preserves physical material fields/albedo, exact direct/area diffuse scattering and stock BRDF/transmission/clearcoat. Glass explicitly receives the original first-two lamp identities and key orientation; cards remain1.6× at1/2.56 intensity. Program keys include transport values and card identities. area-light-nodes.ts expresses the installed LTC evaluator through public TSL with the same branch/winding/constants/accumulation order. Private LTC exports are not mixed with the bundled TSL stack.
- sticker-material-nodes.ts creates the exact front/back StickerPrint pair with borrowed artwork/roughness/environment/damage textures, original alpha threshold, side/depth/finish flags, appearance and wear. Prepared damage is explicit, so the worker factory does not rasterize DOM artwork. Its owner disposes only materials and controller-owned fallback textures. Geometry/renderOrder remain host responsibilities.
- sticker-wear-nodes.ts uses authored seeds, transformed map coordinates, masks, groove derivatives and tint values. Neighbor sampling avoids a second matrix transform. Clearcoat wear executes after stock geometry-roughness processing, matching the old shader insertion; disabled clearcoat remains disabled. Locked/consumed front appearance clears wear properties, preserving the old replacement semantics. A single uniform update changes wear; no shader rebuild.
- sticker-paper-nodes.ts keeps all96segments and original front/back/edge topology, thickness, stable half-angle curl and adjacent-triangle normals. It writes normalLocal before stock normal/bump/clearcoat processing. The existing exact CPU bounds remain the interaction/trajectory contract; the factory does not replace them with approximate bounds.
- composite/lcd-material-nodes.ts makes texture storage color space explicit: raw unorm native sRGB pixels use one exact EOTF; SRGBColorSpace-tagged textures use Three's automatic decode. Both are untone-mapped. Metadata mismatch throws rather than silently double-decode.
- render-backend-services.ts uses an explicit GL/WebGPU union, not a Fiber RootState.gl cast. It owns backend initialization, scene compile and disposal. isInitialized admits a supported backend; isReady admits only the latest completed scene compilation. Starting a compile invalidates readiness. Older completion cannot supersede a newer one. Cancellation/error retires the owner; late init/compile cannot revive it. Init timeout cannot cancel the browser's pending adapter promise, so its eventual result is explicitly disposed; a renderer-worker termination is the final bound for a permanently hung native request.
- Three's default node renderer silently attempts a GL backend on native failure and disables MSAA in compatibility mode. The owner rejects both paths; the host must choose its explicit equivalent GL fallback on a fresh canvas. A failed original backend and any fallback backend are both released. Concrete backend.dispose exists in installed source but is omitted from the installed Backend declaration; the narrow adapter runtime-checks that exact method instead of asserting a renderer type. It never calls Renderer.dispose before init settles, because that method itself reenters init through setAnimationLoop.
- createBackendStudioMaps generates both original studio rooms with the selected canonical PMREM generator and original sigma. Its owner releases both render targets, generator and room geometry/materials; the host restores scene bindings before release.

All node helpers import public bundled exports consistently. An offline identity check proved that deep-source ConvertNode/WebGPUBackend constructors differ from their public bundled counterparts; those early imports were corrected before successful GPU validation.
