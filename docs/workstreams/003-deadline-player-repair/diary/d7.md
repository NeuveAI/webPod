# D7 diary — complete Apple library pagination

**Date:** 2026-09-04
**Implementer:** `/root/d7_library_pagination`
**Status:** blocking live-review correction complete; independent re-review pending

## Outcome

Apple library loading no longer treats MusicKit v1's first bare array as the
whole collection. Every supported library collection request now supplies an
explicit 100-item limit and offset. A full bare-array page issues an opaque
provider-owned continuation; a short or empty page terminates. The existing web
runtime follows those continuations to exhaustion under its unchanged
1,000-page guard.

An authenticated count-only replay after the review correction now reports
112 playlists, 271 artists, 461 albums, and 2,726 songs rather than the former
25-item boundary. No titles, identifiers, authorization URLs, tokens, or media
data were read into evidence.

## Source grounding

The repository-named `~/code/agentic-context/` directory is absent on this
checkout. The implementation was therefore grounded in the repository's pinned
MusicKit verifier and the exact public v1 artifact it validates, rather than in
memory or a different SDK generation.

The pinned artifact retained SHA-256
`0ccb2ab37cedaef2eab9c7044c99afdb8c73a122a29ad8b7344af644a15bd14b`.
Inspection of its public `Library` facade established that the collection
overload accepts a parameters object as its first argument, translates only
`limit` and `offset`, and caps library collection limits at 100. Albums,
artists, playlists, and songs all pass through that collection path. D7 stays
on this v1 facade.

## Implementation decisions

- Fixed the page size at 100, matching the exact v1 facade's own bounded cap.
- Replaced exposed Apple `next` paths with random opaque cursors backed by an
  in-memory continuation map. A cursor is consumed before use, belongs to one
  collection, and cannot be replayed or transferred to another collection.
- Retained structured Music API `next` and `meta.total` behavior behind the
  opaque cursor boundary. Bare arrays report `total: null`; one page's length is
  not the collection total.
- Continued normalization through the existing identity cache and appended
  pages without deduplication. Legitimate duplicate catalog occurrences remain
  in order even when they share the same stable local identity.
- Fingerprinted each full bare-array page from its ordered raw resource type and
  identifier, retained only inside the provider continuation map and never
  logged or exposed through the cursor. If a later offset returns the same
  page, the provider fails immediately instead of looping or claiming
  completeness; malformed records do not collapse distinct pages into the same
  empty normalized fingerprint.
- Cleared unconsumed continuations after a successful sign-out so a cursor from
  one authorization session cannot continue in another.

## Live-review correction

The first live replay after enabling pagination was not valid proof: the
2/4/4/42 counts belonged to the demo fallback. Authentication and the Apple
session were alive, but a later real album record omitted metadata required by
the entity contract. The provider's all-or-nothing page normalization threw,
and the runtime correctly fell back rather than presenting a partial Apple
source as complete.

The provider now isolates normalization at the item boundary. Only its typed
Apple data-validation failures are omitted; unrelated runtime failures still
propagate. An incomplete library record is omitted without invented
title/artist data and without logging any part of the rejected resource.
Pagination still advances from the raw page length, so a full 100-record SDK
page with one omitted item continues to offset 100 instead of terminating at 99
rendered items. Valid records keep their original order and identity. The
exact-page repeat guard remains active.

## Residual risk

The non-advancing guard detects an exact repeated page. A pathological service
that returns overlapping but non-identical pages is still bounded by the
runtime's existing 1,000-page termination guard. Structured responses remain
dependent on Apple's own `next` metadata, as before.
