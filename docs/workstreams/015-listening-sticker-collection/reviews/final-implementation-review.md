### Findings

- **[MAJOR F1] Conflict reconciliation can restore an error state after logout.** `apps/web/src/sticker-runtime.ts:102` checks session generation before starting its 409 inventory refresh, but its nested catch writes `error` without rechecking after the await. Trigger: a placement PUT returns 409, reconciliation GET remains pending, then sign-out aborts the request. Its late rejection changes the freshly reset `signed-out` status to `error`. This violates D5's late-session cancellation contract and presents retry/save failure UI for a collection that has been signed out. Independently reproduced with a fixture provider and deferred mock GET: output was `after logout signed-out`, then `after stale conflict recovery rejection error`. Guard this catch with the same captured generation; add a regression for logout/provider replacement during conflict refresh, not just during bootstrap.

- **[MAJOR F2] An earlier save completion overwrites a newer sticker gesture or selection.** `apps/web/src/sticker-collection.tsx:63–67,116,120–124` guards async continuation using the interaction generation, but selecting another sticker (`:120`) or beginning a new drag (`:70–76`) only stops RAF and never invalidates that generation. The collection buttons remain usable while a save awaits. Trigger: stick A, select or begin peeling B while A's placement request is delayed, then complete A. The old continuation still passes `isCurrent`, applies A's peel/landing continuation to current shared state and clears B's selection; the keyboard continuation also clears B and moves focus. D6 requires interruptible interactions that retain the newest user intent. Invalidate pending presentation completions when a new gesture/selection supersedes them, or deliberately disable conflicting actions during the pending mutation with accessible pending feedback. Keep the successful server placement; cancel only its superseded presentation. Test delayed success and failure with selection/new-pointer action in between.

- **[MAJOR F3] Cancellation does not terminate the complete interaction.** `apps/web/src/sticker-collection.tsx:103` sets stage `open` on pointer cancel but preserves partial pack progress and does not stop an active landing RAF. Cancelling a pack pull at progress 0.3 therefore exposes expanded controls while the physical pack remains mostly below the viewport; cancelling during landing allows stale spring frames to resume writing landing after the reset. The reduced-motion change handler at `:50` cancels shared interaction but leaves `pointerAtom` and captured pointer active, so the next pointer move restarts the supposedly cancelled gesture using its old origin. This fails D6 cancellation coherence and reduced-motion transition requirements. Terminate the scheduler and pointer ownership together, choose a coherent final pack stage/progress, and invalidate obsolete completions. Verify real pointercancel/lost capture during partial pull and landing, plus changing reduced motion while the pointer is down, followed by additional movement and release.
