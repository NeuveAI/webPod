# Cache native panel dimensions outside pose adoption

Status: read-only proposal, not an implementation dispatch. C2 currently owns device-render-host.ts; wait for its frozen handoff and rebase this narrow plan onto that checkpoint. No application, browser, server or build changes were made for this plan.

## Evidence and exact contract

`gpu-production-post-cache-attribution.md` attributes125.021ms sampled self time to offsetWidth under the accepted-pose path in the stopped6.462274s production profile at e9403567. That is sampled getter cost, not an invocation count or proof every call forced layout. It is sufficient to target the repeated box read separately from query/contour work; it is not a promised125ms saving.

At the inspected host checkpoint, adoptPose reads panel.offsetWidth/offsetHeight for projectNativePanel, then assigns the projected transform. Setup appends the panel, assigns authored dimensions, then calls fitPanelContentToFrame before transferring the canvas. html-in-canvas.ts:353 measures the *content* using scrollWidth/offsetWidth; :417 fits that content inside the panel. These are different measurements. Preserve the content-fitting algorithm and native raster/DPR authority unchanged.

The projection cache must contain actual integer offsetWidth/offsetHeight values, not CSS width strings, contentRect, physical pixels, scroll dimensions or transformed getBoundingClientRect. offset dimensions describe the untransformed border box; ResizeObserver observes size changes and does not notify merely because of transforms. Keep the original browser integer result to avoid inventing a rounding policy. Sources: [CSSOM View offsetWidth](https://drafts.csswg.org/cssom-view/#dom-htmlelement-offsetwidth), [Resize Observer introduction and observation contract](https://drafts.csswg.org/resize-observer/#introduction).

## Smallest implementation

Own one dimension record and one border-box ResizeObserver per native host/panel generation. Prefer a tiny private helper only if it makes lifecycle proof clearer; no shared/global cache, dependency, Jotai atom or worker protocol. Proposed source boundary: device-render-host.ts plus optional native-panel-measurement.ts. html-in-canvas.ts stays read-only unless inspection after C2 proves a genuine additional owned dimension writer.

1. After panel attachment, explicit styles and fitPanelContentToFrame complete, read offsetWidth and offsetHeight once and establish the first positive dimensions before normal pose projection. Register ResizeObserver with box:'border-box'. An observer notification is the invalidation signal; refresh via the same offset getters inside that callback. Do not convert inlineSize/blockSize into physical width/height or approximate rounding.
2. Replace only the two getters in adoptPose with the cached record. Keep sequence/epoch/layout checks, query adoption, reliable terminal handling and all downstream projection/carry notifications unchanged. Pure pose updates must have zero panel dimension getters, observer re-registration or content fitting.
3. Extract only the panel-transform calculation/write into a local function usable by both adoptPose and a real dimension change. When the observer obtains a changed valid integer pair, reproject using the latest accepted pose/layout/screen matrix even when motion is idle. Do not call the entire adoptPose again: that would repeat query/controller work and public notifications. Preserve existing identical-transform assignment suppression. Do not add capture filtering or force a second capture; existing paint ownership remains authoritative.
4. Future existing-owner writes to panel width/height/border/padding must refresh immediately after their write batch, before using the new dimensions. Current setup is the only such native writer found. Arbitrary external CSS changes are refreshed by border-box observation before paint; do not claim synchronous knowledge before observer delivery. Do not delay its refresh by an extra animation frame. Window/layout changes continue through existing layout/DPR owners; a changed viewport projection is independent of whether panel dimensions changed.
5. Keep last valid dimensions while document-hidden or CSS-zero/unboxed. Do not pass zero to projectNativePanel or replace an invalid box with guessed authored values. Mark invalid/unavailable and skip only panel-transform calculation until a positive measurement returns; retain query/terminal semantics. Reentry to a visible document performs one fresh measurement before resuming publication; CSS reappearance relies on ResizeObserver. Initial zero waits for a valid box under the existing host readiness timeout rather than certifying a fake panel. Do not read dimensions during hidden pose traffic.
6. Disposal disconnects observation and visibility ownership, clears retained callbacks/references and rejects already-delivered stale callbacks. Replacing the host/panel creates a fresh cache; no old dimensions cross generations. Reuse the host's existing visibility callback rather than adding a parallel listener if practical. No interval or per-frame polling.

Transforms, page scroll and DPR-only changes do not themselves alter these CSS offset dimensions; no separate scroll listener or DPR multiplier belongs in this cache. Real CSS border-box changes during resize/zoom must still be observed. Existing canvas measurement and native pixel transport continue managing viewport/raster changes.
