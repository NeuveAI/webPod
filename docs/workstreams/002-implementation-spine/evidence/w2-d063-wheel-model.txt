D-063 — design-system §9.4 governs wheel motion
================================================

The ruling: §9.4, *The wheel inertia and detent model*, beats pm-spec §4.4's
summary table wherever they disagree. §4.4's columns are trigger, measure,
detent size, dead zone, release and FX — acceleration physics is §9.4's subject
and §4.4's aside. Same shape as §12.0's geometry re-derivation beating §7.3.

What changed, all five transcribed from §9.4 and gated against literals:

  1. Fast-scroll curve   x1 below 720 deg/s · x4 at 720-1080 · x12 above 1080
                         (was §4.4's x1/x3/x7 at 240/540)
  2. Precondition        engages only when the list exceeds 40 rows
                         (§4.4 has no such gate at all)
  3. Velocity ceiling    1440 deg/s, four revolutions a second
                         (§4.4 has no upper bound at all)
  4. Hysteresis          a reversal costs an extra 1.8 deg
                         (§4.4 does not mention it)
  5. Coast floor         21 deg/s = 0.35 deg/frame at 60fps
                         (was §4.4's 60 deg/s)

What §4.4 keeps, because it is the only place these exist: the four input paths
converging on one reducer, per-path measurement, detent sizes, dead zones, the
mouse threshold scaling, per-path FX, release-vs-keyup, the 3-detent smoothing
window — and above all "arrow keys never accelerate, one keydown is one row,
always", which §9.4 does not cover and which nothing here touches. A gate
asserts the keyboard is untouched by the hysteresis for exactly that reason.

⚑ Deferred, not ruled: the haptic conflict (§4.4 "suppressed above 12/sec"
versus §9.4 "only every 3rd vibrates"). §4.4 defers to §9.4's own haptics
specialist §4.9, which has not been read, and haptics are out of scope in this
stage. Neither behaviour is implemented; the seam is left.
