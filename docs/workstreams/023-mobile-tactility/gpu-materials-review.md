## Formula and interface audit

Compared the new factories and helpers against current GL factories/shader hooks and installed Three 0.185.1 sources. Polycarbonate retains albedo scaling and physical fields, with the same additional direct/area diffuse scattering before stock BRDF accumulation. The public TSL LTC evaluator matches installed constants, winding, branch, accumulation and horizon approximation. Installed LightsNode supplies the lightNode field, so the glass identity filter is operative; its first-two key-axis alignment and all-card size/power changes preserve the authored 1.6 and 2.56 factors. Actual scene light identities/order remain a host responsibility.

Sticker front/back material settings match StickerPrint's alpha threshold, side, opacity/depth behavior, finish flag and borrowed maps. Locked/placed front paths replace wear, including removal of its roughness/clearcoat modifications; backing remains unprinted. Wear mask thresholds, seed/hash/noise, neighbor samples, groove/derivative terms and tint order match the GL hooks. Mapped UVs are transformed once; explicit neighboring samples disable a second texture-matrix application. Roughness wear precedes stock geometry roughness, while clearcoat wear follows stock setupVariants, matching the GL insertion order. Fallback damage textures are controller-owned; artwork, prepared damage and environment remain borrowed. The factory receives prepared damage explicitly, so the intended worker path does not invoke the helper's optional legacy damage preparation default.

Paper uses the same 96-grid positions, radius/contraction/bow, thickness, adjacent-triangle normal accumulation and edge triangles. normalLocal is written during position setup before stock normal/bump/clearcoat processing. Existing exact CPU bounds remain necessary for return/admission; the helper does not supply a replacement bounding contract. LCD raw-unorm storage applies the same single sRGB EOTF, while SRGBColorSpace metadata delegates decoding to Three. Mismatched metadata rejects rather than silently double-decoding. These checks establish authored formula correspondence, not pixel-identical backend execution.

Public bundled three/webgpu and three/tsl imports avoid the duplicate private-source TSL runtime issue documented during development. Backend services discriminate actual renderer kinds without casting Fiber gl. The canonical PMREM generators produce both original studio rooms; caller must detach scene bindings before disposing owned targets/generator/rooms. No active renderer selection or existing GL shader path changes are included in this milestone.

## Lifecycle findings

Found and corrected: compile evaluated GL compileAsync before entering the bounded failure handler. Installed WebGLRenderer.compileAsync synchronously calls this.compile before returning a promise, so an onBeforeCompile throw left the owner live and undisposed. Independently reproduced that state. The corrected bounded work thunk now invokes the operation inside its try/catch, retiring and disposing once on synchronous failure without adding a scheduling delay. The added retained case passes independently.

The readiness revision correction is sound: starting a new compile clears readiness, only the current revision can publish it, and an older successful completion cannot overwrite a newer completed revision. Cancellation/timeouts retire the generation; late initialization releases the backend after settlement. Native fallback/backend replacement and compatibility-mode rejection have explicit cleanup. A never-settling adapter request still requires renderer-worker termination as the outer bound.

Found and corrected: native device loss previously left owner readiness true while Three's default onDeviceLost made compile/render return without work. The owner now chains that callback, retires and disposes before forwarding, and restores the previous handler on disposal. The independently rerun native-loss case proves both readiness flags become false, release occurs once, and the prior handler is retained. Host replacement remains CPU-009's responsibility.
