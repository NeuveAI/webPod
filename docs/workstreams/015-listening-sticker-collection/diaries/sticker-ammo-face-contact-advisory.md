## Why this addresses the actual failure classes

The pinned [btSoftBody.cpp](https://github.com/kripken/ammo.js/blob/79190a1f03845794b1bba1777f30037349967658/bullet/src/BulletSoftBody/btSoftBody.cpp) selects SDF_RS at0x01 and CL_RS at0x02; they are alternative rigid/soft modes. SDF_RS tests soft vertices. Even perfect vertex contact can leave a long rendered triangle cutting the body between vertices, so finer SDF/timesteps alone cannot guarantee that surface requirement. CL_RS instead tests a cluster's convex extent. With one cluster per rendered triangular face, the extent is that face, avoiding the coarse-cluster envelope over many material triangles.

The same source's k=0 branch creates one cluster per face when there are no tetrahedra. Its positive-k branch's aggregate master is not executed. Therefore exactly2048clusters are expected here, all marked collidable; generateClusters(0)'s return value must equal2048 or the preflight fails. Its maxiterations parameter controls the positive-k clustering loop and is irrelevant in this branch; omit it rather than pretending it limits per-face connectivity construction. Pin inverse masses before generating clusters, since initializeClusters determines anchor-containing clusters then.

The [native collision implementation](https://github.com/kripken/ammo.js/blob/79190a1f03845794b1bba1777f30037349967658/bullet/src/BulletSoftBody/btSoftBodyInternals.h) tests cluster pairs only when they are not marked connected. Per-face clusters sharing a material node are still excluded. The six prior strictly nonshared face pairs should not be excluded by this rule; report them individually. This does not prove that GJK/contact response will resolve every thin-sheet contact. Adjacent triangles folded through each other remain a separate oracle requirement.

CL_RS consumes the actual concave mesh through its existing [per-triangle convex-hull adapter](https://github.com/kripken/ammo.js/blob/79190a1f03845794b1bba1777f30037349967658/bullet/src/BulletSoftBody/btSoftBodyConcaveCollisionAlgorithm.cpp), whose source extrusion is±.06unit. No alternate box/cap is introduced. CL_RS bypasses the SDF query path, so this configuration should not generate the previous SDF cell growth. The concave child-hull cache still exists; actual heap/time limits remain in force.
