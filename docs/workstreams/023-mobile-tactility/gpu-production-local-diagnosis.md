# Local production contrast startup diagnosis

2026-09-11, read-only application audit. No environment values, credentials, key files, logs, browser storage, or token response bodies inspected. No application edits or server actions.

The reported launcher differs from Vite development in two independently established ways:

1. Installed Bun resolves relative `--env-file=.env.local` after `--cwd apps/web`. A synthetic temporary root/child fixture using the exact argument shape printed the child marker; an absolute env-file argument printed the root marker. Neither experiment used repository environment files. Therefore use an absolute environment-file pathname for the same-origin production comparison.
2. `apps/web/vite.config.ts:86–97` explicitly loads root Apple server configuration and normalizes a relative `APPLE_MUSICKIT_KEY_PATH` against the repository root (`normalizeAppleServerEnv`, lines 22–42). `apps/web/scripts/start.ts` does not run that Vite normalization. Its runtime-key provisioner is a no-op when no inline private-key value is supplied (`packages/server-core/src/apple-runtime-key.ts:11–13`). `appleTokenConfigFromEnv` explicitly rejects a relative or missing runtime path with HTTP503 `invalid_configuration` (`apple-developer-token.ts:48–60`). An absolute env-file pathname alone does not normalize its configured key pathname.

These are source-backed configuration asymmetries, not confirmation of the currently running server's exact error. The narrow discriminator is the developer-token endpoint's HTTP status and error.code only; a successful response body contains a token and must never be logged. `invalid_configuration` identifies config validation; `key_unavailable` identifies signing-key access/import failure. Do not read the production log wholesale to obtain this discriminator.

For the supervisor's local comparison launcher: supply the root env file by absolute pathname, normalize the inherited key-path variable in memory against the known repository root only if it is relative, and invoke the production startup with the resulting environment. Do not print the value, import the Vite config (which has unrelated build/plugin side effects), copy key material, or change production application code for this experiment. Retain the exact same localhost:3000 origin and browser profile. A port change changes origin and is not an equivalent session comparison.

`apps/web/src/routes/webpod.tsx` has no redirect loader and preserves the renderer override. `device-page.tsx:192–199` navigates home when an already-observed session transitions to signed-out. The Apple provider fetches its developer token from the same-origin endpoint before configuring MusicKit (`apple-provider.ts:613–616,1145`); non-success throws a status-only error. Thus server availability should be repaired before interpreting navigation as a routing defect or requesting another login. Exact browser redirect causality remains unproven without the supervisor's runtime phase/status observation.
