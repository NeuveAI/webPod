# Sticker editor design brief

2026-09-06. Designer phase, written before implementation of the new editor. The owner's latest request and screenshot are primary; this brief extends the delivered physical collection and direct manipulation contracts. No product source or Pencil file changed during this phase. Lead scope and independent design review must precede implementation dispatch.

## Context and critique

This is casual physical customization of a personal music player. The user wants to handle an attached sticker and adjust its character, then return to listening. In the supplied screenshot, two cream rectangles (“Your stickers are ready.” and “Pulse Code stuck to your iPod.”) occupy separate areas above the device. They duplicate what the visible artwork already proves and pull attention away from the customized backplate. Neither provides a useful next action. The attached prints look like the objects to operate, but currently an immediate pickup gesture offers no distinct selection/editing state.

Visual priority should be sticker, its local controls, then the collection. Routine notices should disappear from the visual scene. The opportunity is to make a small adjustment feel safe and reversible without opening a general settings screen. Existing material lighting, immutable prints, packet laminate and direct manipulation remain intact; this is not a new visual theme.

## Range explored and chosen arrangement

| Arrangement | Strength | Reason to choose or reject |
| --- | --- | --- |
| On-art transform handles and circular rotation handle | Strong spatial connection; familiar to image editors | Reject as primary: several tiny handles crowd a roughly 100px print and its die-cut silhouette; wear still needs another surface. Touch handles would obscure the art. |
| Persistent side inspector / bottom drawer | Room for every property and explanations | Reject: turns physical customization into a settings dashboard, leaves a large plate present, and competes with the real packet on narrow screens. |
| Small contextual adjustment strip, one active property | Keeps the object visible; native controls remain accessible; closes when finished | Choose. A lightweight instrument beside the print exposes only angle, scale, surface wear and return. It is editor chrome, not pretend cardboard or another collectible object. |

Chosen hierarchy: compact title with sticker name and close action; one row of Rotation / Size / Wear selectors; one native range control with visible label and current value; footer Revert and Apply when dirty. Return to pack is a separate quiet action available in the selected clean state. Keyboard Move is available there too. No explanatory paragraph, success badge, duplicate art preview, general settings or extra cosmetic effects. Rotation is initially active. One control at a time keeps touch access generous without a tall panel.

## Placement and narrow layout

Desktop: use the actual projected visible-art bounds, not the texture rectangle or screen center. Place a roughly 240–280px wide strip 12–16px outside those bounds, preferring the free side toward the viewport edge. Keep 16px viewport clearance and avoid the selected art, packet lip and existing Settings/Reset view controls. Recompute from the same device projection after resize/orientation; do not attach it to a stale DOM coordinate. If neither side fits, choose above/below with the same exclusion bounds.

At 375px: use a compact full-width bottom dock inset 16px and the safe-area bottom, with a target height around 168–192px at default text size. Reserve its actual measured height in the device workspace before editing starts so the entire selected sticker remains above the dock with at least 16px clearance. Collapse or lower the collection packet while editing; retain its prior state for later. Reframe the device once on selection if necessary, smoothly and only before a range/drag begins. Never move the device underneath an active pointer. At large text sizes, allow control content to wrap/scroll inside a bounded dock and reserve that real height rather than shrinking targets. A low sticker must remain visible, not be edited blindly under the dock.

All controls have at least 44px touch regions, existing product typography, restrained dark neutral surface and legible light text. A single surface tone establishes containment; no colored edge rail, excessive blur or stacked borders/shadows. The selected artwork remains the visual reference. Keyboard focus has a complete perimeter ring; selection can use a restrained contact-shadow/tone cue without bright rectangular artwork outlines.

## Gesture statechart

`idle → press candidate → selected → draft → saving → selected`

Alternate paths: `press candidate → carried → placing / own-sheet return → idle`; `draft → cancel → selected`; `saving → failure → draft`; any state → session invalidation → idle.

- Primary pointer down on actual opaque print records sticker identity, source pose, grab point and pointer ownership, but does not lift or write. Transparent corners remain shell/flick territory through existing alpha-aware hit testing. Semantic enlarged keyboard targets remain separate.
- Pointer up inside the existing small movement tolerance selects the attached print. No peel, inventory write or success notice occurs. Press-and-hold without movement also remains selection; no undisclosed long-press requirement.
- Movement beyond a named, tested drag threshold transitions once to the existing physical pickup from the original point; no duplicate click fires on release. The threshold must tolerate ordinary touch jitter while beginning pickup during intentional first movement. Test both sides of the threshold in CSS pixels for mouse and touch; do not use a time delay or require a second gesture.
- Dragging a selected clean sticker closes the strip and uses its saved angle/size/wear. While a draft is dirty, Apply or Revert completes that edit before direct pickup. A drag attempt keeps the flat preview and exposes the same local Apply/Revert actions; it must not silently save, discard, or jump to a different source pose under the pointer. Clean selection always retains immediate threshold-based pickup.
- Clicking blank rear dismisses a clean editor and leaves flick arbitration intact. Clicking another sticker selects it. Dirty dismissal, switching or Escape cancels the unsaved draft and restores the captured source; no write. Pointer cancellation before threshold does not select. Pointer cancellation after threshold retains existing physical return behavior.
- Enter/Space on an attached sticker selects it, replacing the old implicit Enter-to-lift convention. Focus moves to the selected property's control. Native range arrows/Home/End operate values; Tab traverses selectors, active range and actions. Move explicitly enters the existing keyboard lift/arrows/Enter-to-place/Escape-to-return flow. Escape from editor cancels draft and closes, returning focus to its sticker. Editor keys never reach device flick handlers.

## Preview, persistence and bounds

The selected record owns `{stickerId, source placement, draft, revision, phase, active property}` in the shared Jotai store; no closure-only React state. Preview overrides the one rendered attached print without publishing inventory or mounting a second copy. Rotation and size changes redraw on the next frame; they do not wait on network. Apply submits one revisioned mutation for the complete validated placement. Revert restores all edits since opening the editor, with no server request. There is no separate undo history in this scope.

Canonical current contract: rotation −180…180 degrees, width .08… .35 of rear width, x/y normalized; the rotated occupied artwork rectangle must stay within the shared safe zone. UI rotation uses degrees and size uses percent of rear width, not misleading percent of the original PNG. Do not silently move the sticker center while rotating/scaling. Limit requested changes to valid geometry at that center, retain the last valid draft at an edge, and provide a local non-toast bound explanation only when the user attempts an unavailable value. A 0-degree reset is useful as a value action, not an additional permanent tool. Wear is a normalized finite appearance value from 0 to 1. It belongs to the owned sticker and persists through return to its sheet, re-stick and reload; rotation and size remain properties of the placement. The material engineer must define the additive durable appearance contract before implementation; an optional placement-only field is insufficient.

Apply remains visibly pending only inside this strip; suppress repeated submission. Preserve the draft while awaiting acknowledgement, with no success toast. On success replace the draft with authoritative data and close or return to clean selection. On ordinary failure keep draft, show “Couldn’t save these changes.” with Retry / Revert locally, and keep the saved record unchanged. On 409 reconcile the server snapshot, restore that visible authority, and show “This sticker changed elsewhere.” with a deliberate re-edit action; never overwrite a newer revision automatically. Cancel/close while a write is already sent invalidates only the editor continuation: the eventual server outcome still reconciles inventory and may not reopen editor or resurrect an old identity. Return-to-pack is a separate confirmed intent using existing same-ID removal/physical return; failure restores the source and shows an actionable contextual error.

## Materials and motion

Rotation changes orientation; size changes physical footprint; wear changes accumulated handling marks on the laminated vinyl. Wear must be deterministic and alpha-clipped: restrained fine abrasions in the coat and edge scuffing that reveal the substrate locally, not random animated grunge, global opacity reduction, sepia recoloring or edits to approved PNGs. At zero wear (“Original”) preserve today's artwork/laminate, including distress baked into the approved print; at maximum keep title/art recognizable. Raw adhesive underside remains distinct from front coat. The folded matte-laminated paper packet and release liner are not aged by this control. An owned sticker returned to its liner retains its added wear; its empty die-cut seat is unaffected. Locked/unowned artwork uses Original.

The real-world relationship is a handled sticker whose protective coat becomes scuffed; this is an art-directed appearance control, not a claim of measured aging simulation. The material engineer must demonstrate normal-scale unworn/mid/worn differences under the existing rig, plus carry/press continuity and reload persistence. Do not add new per-value shader variants or texture downloads during range input.

Storyboard: select stays flat; strip enters with a short restrained transform/opacity settle. Adjust follows input directly. Revert restores the whole source coherently. Apply confirms through the final material/pose itself. Moving still lifts adhesive, carries and presses with the approved contact sequence; returning still lands in its own vacant seat. Exit is prompt and interruptible. Reduced motion removes autonomous strip/device movement and curl animation while preserving direct pointer following, range preview, focus and failure feedback. Named constants and stage-driven ownership follow Interface Craft; the existing physical renderer legitimately animates geometry, so Neuve's DOM transform-only rule is not misapplied to 3D material work.

## Quiet status policy

Remove visible routine completion and partial-sync notices, including both quoted screenshot strings and analogous placed/returned successes. A partial sample with usable owned inventory is not an actionable failure. Do not replace them with another badge or toast. Screen-reader completion feedback may remain concise and deduplicated in one visually hidden polite region; range values use native semantics instead of announcing every frame.

Actionable sync/artwork/save failures remain visible near the relevant object or retry affordance and keyboard reachable. Empty failed ownership still offers sync retry without advertising an unready packet. An edit/save failure belongs inside the editor; if the editor has been dismissed while a sent write fails, show one small local failure affordance near its sticker or collection with retry/recovery, not a silently dropped error. Session loss clears private content and offers the established authentication recovery.

## Acceptance and review evidence

Required actual-route desktop and 375px captures: clean selection next to both high and low placed prints; angle/size live preview; wear zero/mid/max; failed save local recovery; no routine notices after sync/place/return. A native pointer/touch sequence must prove tap causes no lift/write, threshold drag retains real peel, transparent corners still flick, range input cannot flick, selection switches IDs correctly, and low mobile art remains unobscured. Keyboard selects, adjusts, applies, reverts, moves and returns with focus preserved. Reload must restore all persisted properties; delayed responses/409/logout cannot revive stale drafts. The independently reviewed saved-session restoration remains on the critical regression path.

Quality facets (targets, not claimed achieved): directness 5/5, physical fidelity 4/5, quietness 5/5, recoverability 5/5, mobile reach 4/5. Evaluate from actual normal-scale capture and gesture evidence; a static brief or nonzero shader parameter is insufficient. No changes to earning, user identity, catalogue art, approved pack construction or unrelated startup launchers.
