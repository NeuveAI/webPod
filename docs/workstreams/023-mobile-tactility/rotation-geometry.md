Read-only application-code inspection under rotation-scope.md. Retained bounded experiment: `evidence/rotation/geometry/measure.ts` and `measurements.json`. Ran with Bun against installed Three0.185.1; default DeviceForm and the actual procedural factories. Front/control/display memo factory bodies copied verbatim from Device.tsx into the experiment. No model simplification, tolerance welding, dropped attribute or app edit.

## Actual pipeline

The iPod is procedural BufferGeometry, not a downloaded GLB/OBJ. Device.tsx:314 builds the rear tray and cuts apertures, :331 extrudes and tessellates the crowned front, :426 builds indexed curved wheel/control patches, :492 builds glass/display surfaces; DeviceHardware.tsx:11 builds47 physical connector meshes. `curved-shell.ts:446` emits independent triangle vertices with position/normal/UV/crownCap; `hardware-apertures.ts:63` expands indexed input to triangle vertices while clipping. `hardware-geometry.ts:27` similarly extrudes and computes creased normals. These are entry/form-change construction costs. Their memo dependencies omit orientation, so normal rotation does not rebuild these buffers.

The separate optional desktop hand is GLTFLoader-based (`apps/web/src/hand-cursor/rig.ts:38`) and starts only for hover/fine pointer (`HandCursor.tsx:11`). It does not explain mobile iPod geometry. Download compression of a nonexistent device model cannot solve this pipeline; procedural code/texture download size, decoded geometry memory and GPU upload are different quantities.

The experiment hashes raw bytes of **all** attributes, preserving signed zero and each Float32 bit, then verifies every original triangle's expanded position/normal/UV/crownCap byte-for-byte. Index order retains original triangles/winding. It does not merge by position alone, regenerate normals, remove UV seams, quantize, drop crownCap or alter material groups. CrownCap currently has only construction/test consumers, but keeping it honors the decoded-attribute constraint.

These are typed-array payload counts, not total heap or measured driver allocation. On WebGL, installed `WebGLGeometries.js:65` updates all geometry attributes, and `WebGLAttributes.js:5` allocates buffers/upload with the typed array; :208 updates only when identity/version changes. Thus compact static attributes reduce submitted buffer payload; normal rotation already reuses the GPU buffers and does **not** upload the entire device each frame. Indexing may improve vertex reuse, but no GPU timing or frame-rate improvement is established by this memory experiment.

## Draw structure and lossless batching

Source-derived base color-pass submissions are58:11 chassis/control/display draws plus47 hardware. The wheel label reuses ring geometry but is a second draw, so submitted triangles are232,205 before frustum culling, side rejection or auxiliary passes. This excludes stickers, packet paper, reflection cards, PMREM and any renderer-specific additional passes; it is not a renderer.info measurement.

Hardware already shares exactly six material instances (`DeviceHardware.tsx:18`), but every mesh remains a separate draw. Material distribution: metal5, cavity3, insulator3, orange1, slider2, contact33. All vertices already contain their final local hardware coordinates, with identity per-part transforms. Merging by material can reduce47 to6 draws (41 fewer) without changing any triangle/shader. This requires preserving order within each material, and retained mapping from original triangle ranges to named hardware parts. `probe-raycast.ts:42` exposes objectName, and sticker visibility uses mesh names as collision provenance (:59); a plain merge would change those semantics. An implementation must remap exact hits/provenance or retain a separate query representation and explicitly route all query consumers. Current invisible orientation proxies are filtered out by probe/visibility, so blindly copying that technique is insufficient. Hardware batching is promising but carries more correctness work than exact indexing.

Wheel seam floors share material settings and a rigid transform and could combine2 draws into1; Select and clickwheel move independently, so do not batch their geometry with the chassis. Transparent wheel ink/glass/stickers have explicit order and/or independent transforms. Sticker placement stacking in StickerSurface.tsx:17 must retain its order. No indiscriminate transparent batching is recommended.

## Implementation-ready next boundary

First candidate: an exact-bit immutable index finalizer for generated front/rear geometry, after all clipping/normal/UV operations and before render ownership is installed. Preserve every attribute constructor/itemSize/normalized flag, group/draw ranges, original face order, bounds and source name. Select Uint16/Uint32 safely. Keep original behavior for unsupported interleaved/morph/nonfinite cases rather than approximating. Verify triangle-expanded bytes plus existing curved-shell/aperture/probe/sticker-wrap and shell candidate ray parity. The strongest measured opportunity is the two shells (14,585,288 bytes saved); no requirement to touch already indexed controls.

Do not run the large string-key experiment algorithm per frame or in an input handler. A production implementation should use bounded hash storage and preferably share the existing worker preparation boundary, or create indexed output during immutable construction; benchmark entry CPU separately. An asynchronous post-upload swap incurs a second upload and invalidates geometry-dependent wrap/collision/index owners, so it needs atomic ownership orchestration and must not be sold as free.

Cross-device immutable geometry sharing could avoid duplicate construction and CPU buffers when the same form is mounted more than once. Within one device the ring/decal and shell input proxies already share geometry. Across copies, keys must include all shape-affecting inputs; ownership needs reference counting with eviction/disposal on the last owner. Installed `WebGLGeometries.js:10` deletes attribute buffers on geometry disposal, so unrelated BufferGeometry wrappers sharing attributes are not independently disposable. Geometry sharing saves GPU allocation only inside the same renderer/context; separate WebGL contexts still allocate their own buffers. This is secondary to the single-mobile-device indexing opportunity.

GPU rendering already executes vertex transforms, rasterization and physical material shading. Moving static topology generation to GPU does not remove retained CPU raycast/collision requirements or automatically reduce GPU memory. The immediate lossless geometry optimization is smaller exact indexed buffers; renderer/compute migration is covered by the rendering lane. No quality knob, app edit, frame-rate claim or GPU-time estimate is part of this diagnosis.

## Final implementation and evidence

The accepted production change is **shell-only asynchronous construction**, not the initial all-geometry indexing prototype above. Final baseline21,939,808 typed bytes becomes7,354,520; saving14,585,288 bytes (66.48%). `implementation.json.production` is the authoritative implemented total. The69% figure remains the theoretical full-device maximum, not the shipped result.

`immutable-shells.ts` extracts the original complete front/rear constructors. `immutable-geometry-index.ts` uses raw Uint32 attribute bits with hash collision verification, preserving every Float32 record and triangle order. It accepts only immutable ordinary Float32 attributes; indexed/morph/interleaved/instanced inputs remain untouched. It commits compact arrays only when storage decreases. Geometry identity, groups, bounds, normal/UV/crownCap data and draw order remain. Ray hits retain point/distance/normal/UV/material and faceIndex; face.a/b/c now correctly address the compact geometry's vertex indices. No production consumer of old expanded face vertex IDs was found.

An intermediate host experiment measured255.62ms original construction plus52.98ms finalization. That added synchronous work was rejected for entry. `immutable-shell-worker.ts` now performs entire shell construction and indexing off the main thread. Structured transfer adopts finished attributes and precomputed bounds; no post-upload geometry swap or main-thread normals/index pass occurs. `worker-parity.ts/json` compares actual extracted factory/transferred output to the original factories byte-for-byte, including every expanded attribute, groups and bounds; worker buffers detach as intended. Its CPU timings are offline host work, not phone latency.

`immutable-shell-preparation.ts` suspends before Device's other hooks/publication. Identical form keys share one pair; one session worker handles at most one active plus three queued forms. More callers await a current promise rather than grow a work queue. Worker terminates when idle. Uncommitted/discarded render results expire after30s with at most four unused completed pairs; live owners retain their shared pair. Last-owner cleanup disposes and removes its entry; StrictMode's immediate effect reattachment cancels scheduled eviction. All four shell meshes opt out of Fiber auto-disposal so one device cannot free another device's geometry. Shared rear wrap bindings now restore the preceding live owner when the newest owner unmounts.

Worker failure/transfer error/5s per-job timeout terminates that worker and invokes the original CPU constructors asynchronously, **without** additional indexing. That exceptional compatibility path retains original construction blocking and original larger buffers; no claim removes its CPU cost. A failed original constructor rejects through React's existing graphics error boundary. Haptics' inner whole-scene Suspense keeps Canvas mounted while preventing warmup before geometry; readiness waits actual preparation, and bounded compile failure is reviewed in rotation-review-motion.md.

Final retained checks:840 original-versus-indexed shell rays across seven poses/three material sides preserve hit results; lifecycle covers Suspense, same-form sharing, idle worker cleanup, last-owner disposal, rebuilding disposed entries, stale worker callback rejection, unsupported Worker recovery and shared wrap ownership.31 affected geometry/probe/wrap tests pass; the two source-ownership assertions moved to immutable-shells and their5-test run passes28,431 assertions. No new unit tests. Device/composite/web typechecks and all current geometry source/evidence lint pass. The unrelated existing StudioEnvironment assertion remains separately documented. Rendering engineer provides independent geometry review; no current browser frame-time result is claimed.
