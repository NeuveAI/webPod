# Diary — W7 production click-wheel runtime

The first implementation isolated clocks, timers, media queries, document and
window targets correctly, but its tests stopped at that isolation boundary. The
reviewer proved all three production callback forwards could become no-ops while
38 tests stayed green. The correction moved runtime ownership into a mounted
`CompositeInputBoundary`; its test now drives the exact callbacks handed to the
R3F surface and observes the singleton store.

The earlier refresh test ended at the list boundary, so wrong frame deltas could
clamp to the same row. It now begins at row 500 of 1,000, asserts exact travelled
rows across 15–240Hz, and separately proves different elapsed frames produce
different reducer velocity. The reviewer's `1 / 60` mutation now fails for that
specific reason.

Wheel idle now has an independent literal assertion, a 119ms negative boundary,
the 120ms transition, and last-event rescheduling. The `120 → 20` mutation fails.

The flagged-browser regression was real: a completed arc left focus on `BODY`.
Composite now remembers and restores the panel application. Both a deterministic
mounted test and fresh Chrome 151 show focus on `role="application"` after a real
arc, followed by a working Arrow movement. No `useState`, `useFrame`, tier check,
haptic call, or second production store was introduced.
