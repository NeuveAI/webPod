## Authentication domain and Apple cached-session recovery

Implemented the approved D10/D11 expansion. `@webpod/music-management/auth` owns the Jotai authentication attempt/readiness lifecycle, initial-data and session-change fencing, explicit redirect results, logout and disposal. Typed provider auth connectors distinguish native Apple gesture authorization from Spotify redirect/restore. `/playback` references the existing sole queue/transport manager; production playback consumers now import that namespace. App runtime keeps storage/query/HMR, optional stickers and explicit playback lifecycle composition; its former authentication state machine has been removed.

Live diagnosis found rejected personalized authorization: native core-library403, diagnostic Apple40300 Invalid authentication, successful catalog control, and locally cached SDK authorization. Public MusicKit consumes JSON then exposes a Response in ACCESS_DENIED.data. Recovery uses that actual native shape, not invented parsed error fields: HTTPS Apple origin, matching core collection pathname,403 and ACCESS_DENIED. It excludes catalog/relationships/licensing, developer401 and generic500. The adapter resets the rejected cached user session once, never automatically authorizes, and the next user gesture can obtain fresh authorization. Native request/authorization generations and latest auth intent prevent stale failures/completions from replacing or cancelling a newer login.

Regression evidence maps to `packages/providers/src/apple/auth.test.ts` (cached login/reset/fresh gesture, consumed Response, parallel failures, status/path exclusions, failed reset, old response, old auth after logout, newer successful and newer pending auth); `packages/music-management/src/auth.test.ts` (distinct native/redirect flows, data-load account/null changes, logout and disposal); and `apps/web/src/welcome-entry.test.ts` (real runtime/physical entry and pending-logout manager retirement). Existing raw Apple rejected-logout semantics remain preserved; the common app deliberately retires playback during logout and on failure until a new successful connection.

Lead live evidence: current Apple session now authorized at `/webpod`, library albums461/artists271/playlists112/songs500 during progressive loading. Lead observed after a reload and external/user interaction, so this proves successful real session/library loading under current code, not a fully agent-driven reconstruction of every popup step. No token/header values or signing keys were inspected or recorded.
