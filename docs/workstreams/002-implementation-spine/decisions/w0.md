## 4. "wheelR/bodyW === 0.697" is wheel *diameter* over body width

The packet's acceptance criterion is written `wheelR/bodyW === 0.697`, but 115/330 = 0.348.
§12.0 states the ratio as "Wheel/body = 230/330 = **0.697**" — i.e. diameter over width.

Implemented as the diameter form, exported as `WHEEL_TO_BODY_RATIO` and derived from
`WHEEL_R` and `BODY_W` rather than written down, so it cannot drift from the radii. The
test asserts `0.697` to 3dp and goes red at the pre-R5 `wheelR` 106 (giving exactly the
0.642 §7.3 records as the drift). Reading it as radius-over-width would make the stated
target unsatisfiable, so this is a reading of the packet rather than a deviation.

## 7. Shared config choices, made freely but worth stating

- **`exactOptionalPropertyTypes` is off**; everything else strict is on, including
  `noUncheckedIndexedAccess`, `noImplicitReturns` and `noUnusedLocals`. It interacts badly
  with React prop spreading and would tax four lanes for little safety. Reversible in one
  line if the lead wants it.
- **Geometry constants are annotated `: number`** rather than left as literal types.
  Literal types on a dimension make every arithmetic comparison against them a type error
  and buy nothing. `HALO` and `TRAIL` keep `readonly` members via explicit types.
- **`useState` is banned by lint**, not only by review: `no-restricted-syntax` catches the
  call, the `React.useState` member form and the import. Verified to go red on a planted
  violation.
- **`bun run gates` exits 1** with "not implemented" until W5a lands. A placeholder that
  exited 0 would report "no findings" for checks that never ran.

`packages/ui` has that shape. I made them resolve, because a `components.json` that is
declared but dead is exactly the kind of thing the next lane discovers at the worst moment.

## 13. Follow-up after the re-review (approved, two Minors held as blocking)

### The last two `useState` escapes are closed

`R['useState'](0)` and `const { useState: mk } = R` both linted clean. The reviewer rated
them Minor correctly — you only reach either by trying to get around the rule. Closed
anyway, on the lead's reasoning: **`AGENTS.md` states the law absolutely, with no
qualification.** A stated law with a known hole is worse than an unstated convention,
because it buys false confidence in the one constraint the tool-callback architecture
rests on.

Five selectors now: bare call, any member access, computed string-key access, import
specifier, and `ObjectPattern > Property[key.name='useState']`. Plants J, K and L (the two
named forms plus the shorthand destructure nobody had tried) all go red, recorded in
`evidence/w0-gates-go-red.txt`.

**One accepted imprecision, stated rather than buried.** `MemberExpression[property.name=
'useState']` flags *any* read of a property named `useState`, including on an unrelated
object. Narrowing it to React would reopen the alias hole that was the whole point, and a
non-hook property named `useState` is not a thing anyone writes. The `ObjectPattern`
restriction does keep object *literals* clean — verified with a false-positive plant.

### The rewrite plan's §4 is now tip-independent, and its advice has changed

The recovery block was worse than stale. It called `8f27b02` "the tip commit", took
`HEAD~1`, and fell back to a hash that does not exist inside the rewritten clone.

Beyond fixing those, **the recommendation itself changed, because the facts changed.**
When §4 was written, the rename commit *was* the tip and a collision was one `--amend`
from repair. It is now buried under many commits, so `--amend` cannot reach it and
repairing mid-history means another full rewrite pass. So §4 now:

- finds the commit by **message**, never by hash — every hash from `2305f4b` on is
  different inside the clone, which is the trap the old text walked straight into;
- checks `AGENTS.md` at **every commit from the rename onward**, not just the tip: a later
  commit that writes `AGENTS.md` would mask a hole in the middle;
- states plainly that `--amend` is the wrong tool here, and recovers by discarding the
  clone and redoing pass 1 only;
- **recommends skipping pass 2 by default.** The rename is cosmetic — `git log --follow`
  traverses it either way — while the `.claude/` removal and the trailer strip are the
  load-bearing halves.

§1 also gained a note saying which hashes are valid in which repo, since the descriptive
sections legitimately name pre-rewrite hashes that will not resolve in the clone.

This matters more than its severity because of who walks the path: under D-003 the owner
runs the rewrite alone with no agent watching, and recovery instructions that are wrong
only at the moment you need them are not recovery instructions.
